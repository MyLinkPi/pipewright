# 审批门拒绝/超时：新增「已拒绝」终态 + 审批记录展示 + 不可按节点恢复

## 问题
审批门被拒绝后：门控阶段**从未执行的步骤被标 failed**、运行终态落「失败」，与真实构建失败无法区分；审批决定（谁/何时/批准还是拒绝）已落库 `run_approvals` 且有查询接口，但详情页从不展示。另：审批超时目前落「失败」，应与拒绝同语义。

## 目标语义（已确认）
1. **人工拒绝** → 运行终态 rejected（已拒绝）；门控阶段步骤标 skipped（如实反映未执行），阶段卡片红「已拒绝」徽标，下游照旧跳过。
2. **审批超时** → 同样落 rejected（decidedBy 记 timeout，审批记录显示「审批超时」）。
3. **混合情况**（真失败 + 拒绝/超时并存）→ 终态仍为 failed（真失败优先），拒绝徽标照显。
4. **不可按节点恢复**：父运行的审批记录中存在任一 rejected（人工拒绝或超时）→ 即使终态是 failed 也拒绝恢复（409），提示重新触发新流水线。在门控等待中被取消的运行同样会留下 rejected(canceled) 记录，一并不可恢复（语义一致：人工关闭过审批门的运行不走节点恢复）。
5. 取消（非门控处）/ 审批批准 → 行为不变。

## 后端
1. `internal/run/run.go`：`StatusRejected = "rejected"`；加入 terminalStatuses、allowedTransitions（running→rejected）、isValidStatus；新增哨兵 `ErrGateRejected`（run 包，避免 pool→dagrun 反向依赖）。
2. `internal/run/pool.go`：`runErr` 非 nil 且未被取消（`runCtx.Err()==nil`）且 `errors.Is(runErr, ErrGateRejected)` → `final = StatusRejected`；取消仍落 failed。附带效果：rejected 不触发自动 AI 诊断。
3. `internal/dagrun/dagrun.go`：
   - `dagrun.ErrGateRejected` 改为包装 `run.ErrGateRejected`；
   - 门控人工拒绝：`finishRemaining(StepSkipped)`（替代 StepFailed）+ 记入被拒阶段集合；
   - 门控错误路径：`gerr` 包装 `run.ErrGateRejected`（超时即此类）→ 与人工拒绝同样按 skipped + 被拒集合处理；ctx 取消 → 维持 StepFailed 原路径；
   - 失败汇总拆分：失败阶段**全部**为门控拒绝/超时 → 返回包装 `run.ErrGateRejected` 的错误（含阶段名）；存在真失败 → 维持 pipeline failed。
4. `internal/httpapi/approvals.go`（门 hook）：超时路径错误改为包装 `run.ErrGateRejected`（审批记录仍写 status=rejected、decidedBy=timeout，不变）。
5. **恢复守卫**（`internal/httpapi/resume.go`）：父运行终态校验之后，查 `approvalStore.ListForRun(parentID)`，存在任一 status=rejected 记录 → 409 `run_not_resumable`，人读消息「运行包含被拒绝的审批门,不可按节点恢复,请重新触发新流水线」（approvalStore 为 nil 时跳过守卫）。覆盖：人工拒绝、超时、门控处取消；混合情况（终态 failed）同样被拦。
6. 无迁移；`?status=rejected` 列表筛选自动支持。

## 前端
1. `runs.ts`：`RunStatus` 加 `'rejected'`。
2. `STATUS_CONFIG`（Runs.vue、RunDetail.vue 两处，类型系统强制补全）：rejected 红系配色；文案 `runStatus.rejected`。
3. RunDetail 五态骨架：新增 rejected 分支——DAG 视图 + 审批记录卡片 + 历史日志，**无恢复面板**；failed 态下若审批记录含 rejected → 同样隐藏恢复面板（点击恢复时后端 409 兜底，横幅显示人读消息）。
4. 审批记录卡片（waiting_approval / rejected / failed 均显示）：复用现有 `listApprovals`；每条 = 阶段名 + 待审批(amber)/已批准(绿)/已拒绝(红) + 操作人/超时/取消（decidedBy 为 timeout/canceled 时映射为本地化标签）+ 时间。
5. RunDagView：新增可选 `approvals` prop；阶段有 rejected 记录 → 红色「已拒绝」徽标（gate 徽标保留用于待审批态）。
6. i18n ×8：根文件 `runStatus.rejected`；runDetail.ts 审批记录键（标题/批准/拒绝/待审批/操作人/审批超时/已取消/时间/不可恢复提示）。

## 测试
- dagrun：人工拒绝与超时（gate 返回包装哨兵的错误）→ 错误包装 run.ErrGateRejected、门控阶段步骤 skipped、下游 skipped；混合（真失败+拒绝）→ failed；取消路径 → 维持失败；全批准不变。
- run：状态机 running→rejected、rejected 终态；pool：未被取消时哨兵错误落 rejected、取消落 failed。
- httpapi：带 rejected 审批记录的 failed 父运行 resume → 409；无审批记录的 failed 父运行 → 201 不受影响。
- 前端：vue-tsc + vitest（keyParity/componentKeys 覆盖新 key）+ build。

## 已知边界（写进注释）
- 单账号体系操作人恒为 admin（auditActor 常量）；展示层就绪，多用户落地自动显示真实操作人。
- 历史数据：改动前被拒/超时的运行仍显示失败，不回填。
- 在门控等待中取消的运行会留下 rejected(canceled) 记录 → 一并不可按节点恢复（与「人工关闭过审批门不走恢复」语义一致）。
