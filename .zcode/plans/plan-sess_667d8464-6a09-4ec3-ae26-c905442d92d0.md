# 失败运行按节点恢复：重试 / 跳过单个节点（派生重跑）

## 目标语义
运行失败（或部分失败）后，运行详情页对**每个失败节点（job 级 run_step）**提供「重试 / 跳过」选择，一键创建**派生运行**：
- 父运行中**成功的节点** → 继承为成功，不重跑（日志标注「⏩ 继承自上次运行」）
- 父运行中**失败的节点** → 按用户选择 **retry**（真实重跑）或 **skip**（记为跳过但放行，**下游继续执行**）
- 父运行中**未执行的节点**（被上游失败阻断而 skipped）→ 正常执行
- **部署节点重跑 = 增量语义**：只重试 failed / rolled_back / pending 的机器，已成功机器跳过不重复部署（用户已确认并入）
- 父运行历史不动，子运行记录 `resume_of_run_id` 溯源，可失败后继续恢复（链式）
- 全局可用，无需任何流水线/项目配置

## 后端

### 1. 迁移 `0067_run_resume.sql`（sqlite + mysql 双份）
`pipeline_runs` 加两列：`resume_of_run_id TEXT NOT NULL DEFAULT ''`、`resume_plan_json TEXT NOT NULL DEFAULT ''`（按 ordinal 的动作数组，如 `["inherit","retry","skip","run"]`）。`deploy_targets` 表无需改动。

### 2. `internal/run`（领域层）
- `run.go`：新增 `NodeAction` 常量（`inherit|run|retry|skip`）、`ResumePlan{ParentRunID string; Actions []NodeAction}`；`Run` 增加 `ResumeOfRunID string`、`Resume *ResumePlan`；`StepDecl` 增加 `Initial string`（继承/跳过节点 Plan 时直接落终态）。
- `service.go`：
  - `Create` 的 INSERT 与 `Get` 的扫描补 resume 两列。
  - 新增 `CreateResume(ctx, parentID, actions map[int]NodeAction, actor string)`：校验父运行终态（failed/partial_failed）→ 复制父 trigger（branch/commit/params/解析环境与目标机，type=manual 使 when 条件行为一致，actor=操作人）→ 写入 resume 列 → **复制父运行全部 `run_artifacts` 行**（保证 `restorePriorArtifacts`/镜像引用可用）→ **复制父运行全部 `deploy_targets` 行**（部署增量重试的状态基线）→ 复用既有 enqueue。
- `pool.go` `dbStepSink.Plan`：按 `StepDecl.Initial` 插入初始状态（终态时同时落 finished_at）。

### 3. `internal/dagrun`（执行编排）
- **提取节点布局**：把 `Runner.Run` 中「ExpandMatrix → BuildGraph → 拓扑序 → decls/jobOrdinals/stageFirstOrd」提取为 `NodeKey{StageID,StageName,JobID,JobName}` + `NodeLayout(stages)`，Runner 与恢复校验共用（配置未变 ⇒ ordinal 恒对应）。
- **恢复计划校验** `BuildResumePlan(cfg, parentRun, req)`：逐 ordinal 比对节点名（不一致 → `spec_changed`）；生成全量动作数组（success→inherit、failed→用户选择、其余→run）。
- **Runner 应用恢复计划**（`dagrun.go`）：
  - Plan 时按动作写 `Initial`（inherit→success、skip→skipped）。
  - 阶段回调最顶部（早于 when/Gate，纯继承/跳过阶段不触发审批门）：预标记 inherit/skip 节点已收尾（stageReporter 加 `markPreset`）；构造**过滤后的 stage 副本**（只含 retry/run 的 job，needs 重映射到保留节点）传给 `r.exec` —— 执行器零改动；无可执行 job → 记日志后放行下游。
- **遗留 runner 防御**：resume 运行被非 DAG runner 执行时快速失败并写明原因。

### 4. `internal/deploy`（部署节点增量重试）
`DeployForStage`（deploy.go:339）与 `runCommandOnly`（命令型部署）入口处：经 `s.runs.Get(ctx, runID)` 发现 `Resume != nil` 即启用增量语义——
- 目标机过滤：selector 解析后，**已 success 的机器跳过**（返回带「已成功，跳过重部署」消息的结果供节点日志逐机展示），只对 failed / rolled_back / pending 及选择器新增的机器执行部署；全部已成功 → 返回非空跳过结果，节点直接放行。
- 持久化由 `SaveDeployTargets`（整批覆盖）改为 **`UpsertDeployTargets`**（逐目标 upsert，保留未涉及机器的继承状态）。
- `deploy.Service` 接口签名零改动；`RetryFailed` 既有路径不受影响。

### 5. `internal/httpapi`
- DTO 追加字段（additive）：`stepDTO.Ordinal`、`runDetailDTO.ResumedFrom *string`。
- 新路由 `POST /api/runs/{id}/resume`（auth+CSRF；新增 `resume.go` handler）：body `{actions: {"<ordinal>": "retry"|"skip"}}`，仅允许父运行的失败节点；错误映射 404 / 409（非终态、`spec_changed`）/ 422（无失败节点）；`recordAudit`；返回子运行 DTO（201）。
- 新 Option `WithSpecLoader(dagrun.SpecLoader)`，main.go 注入既有 `specLoader`（main.go:437 同一实例）。

## 已知限制（写进日志/文档）
- 被跳过节点的 `$PIPEWRIGHT_ENV` 输出不可用：重跑其下游节点时拿不到它的环境变量（工作区各自独立克隆）。
- 恢复创建时校验配置一致性；若创建后、执行前 spec 又变，运行以明确错误失败（不静默全量重跑）。
- 恢复运行中部署节点被「跳过」时，targets 面板保留父运行最后部署状态（如实反映现实：该机仍是当前线上状态）。
- 恢复运行的所有部署节点均为增量语义（只推失败/未部署机器）；如需全量重部署可新建普通运行。
