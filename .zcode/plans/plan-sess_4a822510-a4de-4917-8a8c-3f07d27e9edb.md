# 平台 HTTPS 访问:宿主 nginx 自动配置(证书 + 80→443)

## 需求

当(平台可管理到的)机器上装有 nginx 时,允许在 UI 配置**平台自身 Web 页面**的 HTTPS 访问:选择访问域名 + 复用「证书管理」的证书,平台经 SSH 自动完成:下发证书文件 → 写 `/etc/nginx/conf.d/` vhost(443 ssl 反代平台 Web 端口 + 80→443 跳转)→ `nginx -t` → reload;证书续期后自动更新证书并 reload;支持禁用并清理。

与既有 servicereg 网关(平台自管的 nginx **容器**)互不影响,本功能面向**宿主机自装的 nginx**,只写自己的文件(`conf.d/pipewright-platform.conf` + `/etc/nginx/pipewright/certs/<域名>/`),与用户已有配置共存。

## 后端

### 1. 迁移 0056(`internal/store/migrations/{sqlite,mysql}/0056_platform_https.sql`)

单行设置表 `platform_https_settings`(`id=1` 单行,照抄 `service_reg_settings` 手法):`enabled`、`server_id`(nginx 所在已登记服务器)、`domain`(访问域名)、`cert_id`(certificates 引用,软引用)、`upstream_host`(默认 127.0.0.1)、`upstream_port`(0=用平台自身端口)、`http_redirect`(默认 1)、`status`('' | active | failed)、`status_detail`、`last_applied_at`、时间戳。

### 2. 新领域包 `internal/platformhttps/`

- `platformhttps.go`:`Settings`/`NginxDetect` 模型、`Service` 接口(`Get/Save/Detect/Apply/Disable`)、校验(域名 regex 与 certmgmt 同规则;证书须 issued 且 SAN 覆盖域名——`domainCoversAny` 同款逻辑;upstream host 白名单、端口 1..65535)、领域错误(`ErrNoNginx`/`ErrNoPrivilege`/`ErrCertNotReady`/`ErrCertNotCover`/`ErrApply` 等)。
- `render.go`:纯函数 `renderPlatformConf`,golden 可测。要点:`map $http_upgrade` WS 头、80 块 `return 301 https://$host$request_uri`(http_redirect 关时改为反代同 443)、443 ssl 块挂 `/etc/nginx/pipewright/certs/<域名>/{fullchain,privkey}.pem`、`ssl_protocols TLSv1.2 TLSv1.3`、`client_max_body_size 512m`、`proxy_read/send_timeout 3600s`(SSE 日志流)、`proxy_set_header Upgrade/Connection`(WS 终端)、`X-Forwarded-Proto https`。仅 IPv4 `listen`。
- `nginx_ops.go`:SSH 执行序列,全部 array 形式(AC-SEC-02):
  - `Detect`:`nginx -v`、`id -u`、非 root 时 `sudo -n true`、`nginx -T` 是否 include conf.d(best-effort)、是否已存在平台管理的配置。
  - `Apply`(提权前缀 = root 为空 / 非 root 为 `sudo -n`,不可用报人话指引):取证书 PEM → Upload 三份临时文件 → `mkdir -p` + 安装证书(私钥 600)→ 备份旧 conf → 安装 conf.d 文件 → `nginx -t` 失败则**回滚备份**再报错 → reload(`nginx -s reload`,失败 fallback `systemctl reload nginx`,均失败给人话,不自动 start)→ `nginx -T` 校验我们的标记真的被 include(防 conf.d 未被 include 的静默失效)→ 更新 status。
  - `Disable`:移除 conf.d 文件与证书目录 → `nginx -t` → reload;设置行保留 `enabled=0` 便于再启用。
- `store.go`:get-or-default + upsert(照抄 servicereg store 模式)。

### 3. certmgmt 集成(续期自动重下发 + 删除保护)

- `internal/certmgmt/certmgmt.go`:
  - `Service` 接口新增 `OpenCertPEM(ctx, id) (certPEM, keyPEM string, err error)`——进程内解密(PEM 仍绝不过 HTTP),供 platformhttps 消费。
  - 新增可选依赖 + setter(照 `SetCertSink` 模式):`type PlatformHTTPS interface { UsesCert(ctx, certID) (bool, error); RedeployCert(ctx, certID) error }`,`SetPlatformHTTPS(p)`。
  - `issueCert` 成功后、`Renew` manual 分支、`Import` 的 `syncGateway` 调用点旁:best-effort 调 RedeployCert(失败仅 append status detail,不回滚)。
  - `Delete`:若 `UsesCert` 为真 → 新错误 `ErrCertInUse`(人话:平台 HTTPS 正在使用,请先更换或关闭)。
- `cmd/pipewright/main.go`:构造 `platformhttps.New(db, targetSvc, certSvc, 默认端口)`(默认 upstream 端口取自 `cfg.Addr`);双向装配 `certSvc.SetPlatformHTTPS(adapter)`;`httpapi.WithPlatformHTTPS(...)`。

### 4. HTTP 层(`internal/httpapi/platformhttps.go` + `router.go`)

`/api/platform-https` 路由组(`WithPlatformHTTPS` Option,照 certmgmt 挂载方式):
- `GET /settings`(join 服务器名/证书摘要;DTO 不含 PEM)
- `PUT /settings`(可带 `apply=true` 保存后立即应用)
- `GET /detect?serverId=`
- `POST /apply`、`DELETE ''`(禁用清理)

GET 需 auth;写操作 auth+CSRF+audit(audit action 命名照抄现有风格)。
