# 批量执行命令功能实现方案

在「服务器状态」页(/server-status)集成批量命令:勾选多台机器 → 输入命令 → 同步执行 → 逐机展示结果;危险命令需输入文字强确认;执行历史持久化到数据库并可回看/重跑。

## 后端(Go)

### 1. 数据库迁移(新增 2 个文件)
- `internal/store/migrations/sqlite/0053_server_commands.sql` + `internal/store/migrations/mysql/0053_server_commands.sql`(go:embed 自动发现,无需注册代码;两方言各按现有风格写)
- 表结构:
  - `server_command_runs`:id TEXT PK、command TEXT、total/ok_count/fail_count INTEGER、created_at——一次批量执行的头部
  - `server_command_results`:id 自增 PK、run_id FK→runs ON DELETE CASCADE、server_id、server_name、ok、exit_code、stdout、stderr、error、duration_ms——逐机结果
  - 索引:`idx_server_command_results_run_id`
- 插入时自动裁剪:仅保留最近 200 次运行(防输出大 blob 无限膨胀)

### 2. 新领域包 `internal/servercmd/servercmd.go`
- `Service{db *sql.DB, targets target.Service}`,`New(db, targets)`;装配点 `cmd/pipewright/main.go`(targetSvc 已存在,加一行 + Option)
- `Run(ctx, RunInput{Command, ServerIDs, Timeout}) (*RunResult, error)`:
  - `targets.List` 一次解析 id→Server(拿到展示名);未知 id → 该机 per-item 错误,不整体失败
  - 并发模式照抄 `server_containers.go:228`:信号量 6 + WaitGroup + 预分配 `items[i]`(无锁)
  - 每机 `context.WithTimeout`(默认 60s,5~300s 钳制);执行用 `targets.Exec(ctx, id, []string{"sh", "-c", command})` —— `sh -c` 走 `Upload`(target.go:512)已有先例;每台一条新 SSH 连接
  - 错误处理照 `server_ops.go`:连接/认证类错误 → 该机 ok:false + 人读文案(复制 humanServiceError 的 ~15 行映射);非零退出码 → ok:false + stderr
  - stdout/stderr 各截断 64KiB;结果落库(事务写 runs+results;落库失败仅记日志,不影响返回)
- `ListRuns(ctx, limit)` / `GetRun(ctx, id)` 历史查询
- 常量:并发 6、命令长度上限 8KiB、机器数上限 100、超时 5~300s

### 3. HTTP 层
- `internal/audit/audit.go`:新增 `ActionServerCommand = "server_command"`
- 新文件 `internal/httpapi/server_commands.go`(handler 范式照 `server_ops.go:128`):
  - `POST /api/servers/commands/batch`:MaxBytesReader → 校验(命令非空≤8KiB、serverIds 1~100、去重,非法 400)→ `svc.Run` → 响应 `{runId, items[], summary{total,ok,failed}}`,逐机失败不 500;写审计(detail:命令截 256 字 + 计数 + runId)
  - `GET /api/servers/commands/runs?limit=50`:历史列表(不含输出)
  - `GET /api/servers/commands/runs/{runId}`:历史详情(含逐机输出)
- `internal/httpapi/router.go`:servers 段(~:786 terminal 之后)注册 3 条路由;chi 字面段优先于 `{id}`,与现有 `/servers/metrics` 同理不冲突;新增 Option `WithServerCommands`
- POST 自动过 auth+CSRF(中间件对 /api 组统一生效,无角色权限概念,与现有写端点一致)

### 4. 后端测试

## 关键取舍说明
- `sh -c` 任意 shell 字符串是本功能本质;平台为单管理员,现有 WS 终端(单机)本就能执行任意命令,批量入口不提升权限面。缓解:auth+CSRF、审计留痕(命令+结果计数)、前端危险强确认、输出/超时/并发/机器数四重上限
- 同步返回而非 SSE 流式:单机超时上限 300s 覆盖绝大多数运维场景,复杂度低一个量级
- 历史裁剪 200 条:防 64KiB 输出 blob 撑爆库;审计日志(append-only)仍完整保留每次执行记录
