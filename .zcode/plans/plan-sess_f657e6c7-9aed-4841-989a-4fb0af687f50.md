# 实例级轮转升级：服务多实例 + 实例摘/挂 + instance_rolling 默认策略

## 总体

服务注册网关（nginx）从「一服务一上游」升级为「一服务 N 实例」（每实例 = 网关同机一个具名容器），deploy 新增 `instance_rolling` 策略并**设为默认**（原 rolling/canary/blue_green/interactive 保留不动）。每个实例按「起新 → 预热健康 → 原子切换（一次 reload）→ 短 drain → 停旧」替换，新实例健康后才切流量，任何时刻不为零后端，单实例服务也零停机。无匹配网关服务或非 image 产物时自动回退现有单机滚动，存量部署行为不变。

## 1. 数据模型（migration `0051_service_reg_instances.sql`，sqlite+mysql 双份）

`service_reg_instances(id, service_id, container, port[0=继承服务端口], attached, 时间戳, UNIQUE(service_id, container))`。存量迁移：既有 http+container 服务的单一 upstream 自动 seed 为实例 #1（sqlite 用 `hex(randomblob(16))`、mysql 用 `UUID()` 生成 id）。

## 2. servicereg 领域层

- **模型**：`Instance{ID, ServiceID, Container, Port, Attached, 时间戳}`；生效端口 = 实例端口>0 否则服务 `upstream_port`。
- **渲染改**（`renderNginxConf(domains, services, instances)`）：http+container 服务渲染为 `upstream pw_<name> { server <c>:<p> max_fails=2 fail_timeout=10s; ... }` + `proxy_pass http://pw_<name>;`（成员 = attached 实例）；**全部摘除 → 该 server 块 `return 503`**（维护态，且避免空 upstream 非法）；address 上游与 tcp 服务保持现变量+resolver 形态不变。注意：upstream 块内 server 名在 reload 时解析（nginx OSS 语义），平台每次变更/轮转都伴随 reload，容器名解析始终新鲜。
- **apply 加自愈**：渲染前对每个 attached 实例 `docker inspect` 探活，容器已不存在的实例**静默剔除**本次渲染（否则 `nginx -t` 会因 "host not found in upstream" 整体失败，一个死实例卡死全部配置变更）；`connectUpstream` 改为按 attached 实例逐个接入网络。
- **Service 接口新增**：`ListInstances / AddInstance / RemoveInstance / SetInstanceAttached`（均触发 apply）；`SwapInstance(serviceID, oldContainer, newContainer)`——实例行原子改名 + 单次全量 apply/reload（deploy 轮转的切流量原语）；`ResolveDeployInstances(serverID, container)`——deploy 侧反查：实例容器名精确匹配 **或** 服务名匹配（abc → 实例 abc-1/abc-2…）、serverID 须等于网关主机、仅 http+container，返回 `DeployInstance{ServiceID, ServiceName(FQDN), InstanceID, Container, Port(生效)}`。
- `CreateService`（http+container）自动创建实例 #1，单实例 UX 不变。
- 单测更新+新增：多实例 upstream golden、全摘 503、seed 迁移、Swap 命令序列（单次 reload）、ResolveDeployInstances 匹配规则、死实例剔除。

## 3. httpapi

`GET/POST /api/servicereg/services/{id}/instances`、`DELETE /api/servicereg/instances/{id}`、`POST /api/servicereg/instances/{id}/attached {attached}`；审计 action `servicereg.instance.*`。handler 测试覆盖实例 CRUD + 摘挂触发 reload。

## 4. deploy：`instance_rolling`（新文件 instance_rolling.go）

- **晚绑接口**（deploy 不 import servicereg，照 previewenv 钩子规矩）：
  `InstanceGateway { ResolveInstances(ctx, serverID, container) ([]InstanceRef); SwapInstance(ctx, serviceID, old, new) error }` + `WithInstanceGateway` Option。
- **策略**：`StrategyInstanceRolling = "instance_rolling"`；`NormalizeStrategy` 空串/未知 → `instance_rolling`（新默认）；`deployWithStrategy` 路由：instance_rolling 仅对 **image 产物** 且装配了 InstanceGateway 且 ResolveInstances 非空时走实例轮转，否则回退 `deployImageOne`/`deployOne`（与今天行为逐字节一致）。更新 strategy_test 默认断言。
- **单机执行序**（对服务的每个 attached 实例）：
  1. `docker pull` 新镜像（预备，不动旧容器）；
  2. `docker run -d --name <旧名>-r<rand6> [runArgs] <ref>` 起新实例（旧实例继续服务；runArgs 含宿主端口冲突 → 失败并提示「网关托管实例不应发布宿主端口」）；
  3. **预热健康**：hc=http → 探测 URL 重写为 `scheme://<容器IP>:<生效端口><path>`（容器 IP 经 `docker inspect {{range .NetworkSettings.Networks}}{{.IPAddress}}` 取，宿主 curl 直达容器网段）；hc=command → 原样跑；无 hc → 容器 Running settle 检查（2s × 3 次）；
  4. `SwapInstance`（一次 reload 原子换 upstream 成员）；
  5. drain：sleep `cfg["drainSeconds"]`（默认 5，夹 0–60）等存量请求；
  6. `docker rm -f` 旧实例容器。
- **失败语义**：步骤 2/3/4 失败 → `rm -f` 新容器、保留旧实例、该机 failed 并**中止其余实例**（未动实例保持旧版本）；步骤 6 失败仅记告警（已切换）。成功 message 列明各实例替换。
- 单测（fake gateway + fake target）：成功序列、预热失败不调 Swap、无匹配回退旧滚动、默认策略归一化。

## 7. 明确不做 / 已知取舍

- tcp 服务与 address 上游仍单上游（TCP 轮转后续）；外部手工 rm+run 重建的容器 IP 变化不再被变量解析自动跟随（upstream 块为 reload 时解析，平台内变更均有 reload 兜底）——在代码注释与实例提示中文档化。
- drain 为固定等待窗口（OSS nginx 无主动连接排空），严格的逐连接排空需商用 nginx/前置层，注释标明。
