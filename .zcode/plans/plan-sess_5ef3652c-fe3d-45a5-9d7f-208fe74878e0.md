# PVE 集群纳管 + 服务器池 实施计划

## 目标

1. **服务器池概念**：新表 `server_pools`；`servers` 加 `pool_id`/`kind` 列；存量服务器回填 `default` 标准池。
2. **PVE 自动登记**：登记 PVE 物理机时 SSH 探测（`pveversion` → `corosync.conf`/`pvecm nodes`），自动创建 PVE 集群记录 + `pve-<集群名>` 池，同凭据登记其余兄弟节点（已存在的按 host 归池不重建），幂等去重（集群名唯一）。
3. **构建/部署拦截**：`kind=pve_node` 的机器不允许作为构建机、流水线部署目标（显式/钉单机/标签/重试回放/静态网关全路径）、appstore 部署目标。域层哨兵错误 + httpapi 422 映射。
4. **PVE 管理面 P0**：Token 保管（vault 密封）+ 连通测试；集群总览（版本/quorum/节点/资源汇总）；VM 与 LXC 列表；电源操作（默认 readonly=1，解锁+审计）；任务中心（UPID 轮询）。

## 一、迁移 0084（双方言，零注册——embed 自动拾取）

`internal/store/migrations/sqlite/0084_pve_pools.sql` + `mysql/0084_pve_pools.sql`：

- `server_pools(id PK, name UNIQUE, kind 'standard'|'pve', cluster_id DEFAULT '', created_at, updated_at)` + name 唯一索引
- `pve_clusters(id PK, name UNIQUE, api_url DEFAULT '', token_name DEFAULT '', token_sealed BLOB NULL, tls_mode 'verify'|'insecure'|'fingerprint' DEFAULT 'insecure', tls_fingerprint DEFAULT '', state 'created'|'ready' DEFAULT 'created', readonly DEFAULT 1, created_at, updated_at)` + name 唯一索引
- `ALTER TABLE servers ADD COLUMN pool_id ... DEFAULT 'default'`、`ADD COLUMN kind ... DEFAULT 'standard'` + `idx_servers_pool`
- 插入单例 `('default','default','standard','','1970-01-01T00:00:00Z',...)`（固定时间戳，避免双方言时间函数差异；sqlite 用 `INSERT OR IGNORE`，mysql 用 `INSERT IGNORE`；**MySQL 侧新列用 VARCHAR(64)/VARCHAR(16)**，TEXT 不能带 DEFAULT；字符串字面量内不出现 `;`）
- 头部中文设计注释（对齐 0083 风格）：token 只存 SealSecret 密文 BLOB、readonly 默认、kind 系统管理不进更新 API

## 二、target 层（internal/target/target.go）

- `Server` 结构体加 `PoolID string`、`Kind string`（注释：系统管理字段，仅 pveadmin 探测流写入）；常量 `KindStandard="standard"`、`KindPVENode="pve_node"`、`DefaultPoolID="default"`；辅助 `IsPVENode()`
- `CreateInput` 加 `PoolID/Kind`（空→default/standard；校验 kind 枚举、pool 存在）；**`UpdateInput` 不加**（kind/pool 不可经 API 手改，消除 standard→pve_node 转换的历史部署目标问题）
- 新 Service 方法 `SetPlacement(ctx, serverID, poolID, kind string) error`：校验存在性+枚举后 UPDATE；**置为 pve_node 时同时清空 labels/max_builds**（自动退出构建机池，双保险）
- 新哨兵 `ErrPVENotTarget = errors.New("target: pve node is not a build or deploy target")`（供 deploy/runner/apps/httpapi 统一 errors.Is 映射 422）
- Create INSERT / List SELECT（LEFT JOIN server_pools 取 pool_name）/ Get / Update / scanServer 全部加两列
- `internal/httpapi/servers.go`：`serverDTO` 加 `poolId/poolName/kind`；create/update 请求体**不**接受这两字段

## 四、internal/pveadmin 领域层（新建包，对齐 redisadmin/ceph 模式）

**pveadmin.go** — 包注释纪律（token 密封绝不落日志/响应/审计；错误不带凭据；readonly 默认；入参白名单）+ 哨兵错误（ErrNotFound/ErrNameTaken/ErrInvalidInput/ErrVaultUnconfigured/ErrClusterNotReady/ErrReadonly/ErrConnectFailed）+ 直写 SQL CRUD + `New(db, vlt, servers target.Service)`。Service 方法：

- `OnServerRegistered(ctx, serverID) (*DiscoveryResult, error)`：探测流（见 probe.go）；非 PVE → `(nil,nil)`；SSH 失败尽力而为不报错。流程：探测 → 集群按名 upsert（唯一冲突→查询既有）→ `SetPlacement(seed, pool, pve_node)` → 兄弟节点逐个：`SELECT host FROM servers` 全集按 host 精确匹配，已存在→SetPlacement 归池，不存在→Create 占位（同 user/credential/port，kind=pve_node，Labels 空）。DiscoveryResult{ClusterName, PoolID, CreatedSiblings, AttachedCount} 供登记响应提示
- `ListClusters/GetCluster`（DTO 出 hasToken bool，绝不出密文）
- `SetToken(ctx, id, apiURL, tokenName, tokenSecret)`：https URL 校验 + tokenName 格式校验（`user@realm!tokenid`）+ SealSecret 落库，随后立即测连，成功→state=ready，失败→保持 created 并把测试错误返回（token 已保存）
- `TestCluster`：/version 往返
- `SetReadonly(id, bool)`；`DeleteCluster`：先把池内 servers 归位（kind=standard, pool=default）再删池与集群行
- `Overview`：/version + /cluster/status（节点/quorum）+ /cluster/resources 聚合
- `ListVMs`：/cluster/resources?type=vm（vmid/name/node/type qemu|lxc/status/cpu/maxcpu/mem/maxmem/uptime）
- `VMAction(ctx, id, node, vmid int, action)`：action 白名单 start|shutdown|stop|reboot|reset|suspend|resume；node 名正则 + vmid 100..999999999；readonly→ErrReadonly；POST /nodes/{node}/{qemu|lxc}/{vmid}/status/{action}，返回 {node, upid}
- `TaskStatus(ctx, id, node, upid)`：GET /nodes/{node}/tasks/{upid}/status（upid 做 URL 转义）；`ListTasks(id, limit)`：/cluster/tasks

**probe.go** — Runner 接口（`Run(ctx, serverID, cmd)`，照抄 ceph exec.go 的 root/sudo -n privilegePrefix 模式，privTTL 缓存）：
1. `pveversion` exit 0 → 是 PVE；失败 → 非 PVE 结束
2. `cat /etc/pve/corosync.conf` → 解析 `cluster_name` + `nodelist`（node.N.name / node.N.ring0_addr）；无此文件 → 单机 PVE，集群名取 `hostname -s`，节点=自身
3. cat 失败（无特权）→ `pvecm nodes` 兜底解析
- 命令一律固定 argv；fixture 单测覆盖三种解析

**client.go** — `pveClient` 接口（Get/Post，注入可测）+ liveClient：`Authorization: PVEAPIToken=<name>=<secret>` 头；TLS 三模式（insecure / fingerprint=证书 SHA256 固定 / verify=系统 CA，经 VerifyPeerCertificate 实现）；10s 超时；PVE JSON 怪癖（数字即字符串、0/1 布尔）用 `flexInt/flexFloat/flexBool` 自定义 UnmarshalJSON 收口在此一处；非 2xx 解析 PVE 错误体 → ErrConnectFailed 包装（绝不含 token）

## 五、httpapi 层

**internal/httpapi/pveadmin.go**（新）：
- 点分审计常量（`pveadmin.cluster.token` / `.test` / `.readonly` / `.delete` / `pveadmin.vm.action`，对齐 redisadmin 风格）+ `writePVEAdminError`（NotFound 404 / NameTaken 409 / InvalidInput 422 / VaultUnconfigured 503 / ClusterNotReady 409 / Readonly 409 / ConnectFailed 502）+ `mountPVEAdmin(ar, svc, aud)`
- 路由（admin 组 `/api/pve/*`）：GET `/clusters`、GET `/clusters/{id}`、PUT `/clusters/{id}/token`、POST `/clusters/{id}/test`、PUT `/clusters/{id}/readonly`、DELETE `/clusters/{id}`、GET `/clusters/{id}/overview|vms|tasks`、POST `/clusters/{id}/vms/{node}/{vmid}/status`、GET `/clusters/{id}/task?node=&upid=`
- 电源操作成功/被拒均审计；请求体 ≤64KiB、action 白名单二次校验

**internal/i18n/messages_pveadmin.go**：zh-CN 源串 + en/ja/ko/es/fr/de/zh-HK 七语种译文（register 模式）

**cmd/pipewright/main.go**：`:451` 附近构造 `pveAdminSvc := pveadmin.New(st.DB, credVault, targetSvc)`；`:767` Option 链加 `httpapi.WithPVEAdmin(pveAdminSvc)`
