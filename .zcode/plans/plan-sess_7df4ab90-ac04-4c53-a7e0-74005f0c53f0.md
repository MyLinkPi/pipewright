# Pipewright 增加 Passkey(WebAuthn)+ TOTP 二步验证(修订版 3)

参考 new-api 实现,适配 pipewright 架构。管理员与普通用户(member)均支持。本次新增「会话体验修复」一节,解决被动登出与登出后卡死问题(与 2FA 的 30 天会话互为前提)。

## 一、会话体验修复(随本次一并落地,响应反馈)

诊断结论:多设备登录本就支持(每次登录独立会话行);被动登出根因是 **cookie `Expires` 只在整页加载时重发,与 DB 滑动续期脱节**(长开不刷新的标签页 cookie 固定 7 天后过期);登出后卡死根因是 **SSE/WebSocket 不走 fetch 封装的统一 401 跳转**(EventSource 看不到状态码、无限自动重连)。

1. **后端:滑动续期时同步重发 cookie。** `SessionStore.Get` 在写库刷新(60s 节流)时向调用方返回「已刷新」标记;`requireAuth` 命中该标记时调用现有 `setSessionCookies` 重发两个 cookie(Expires=新的滑动到期)。长开标签页不再被动登出;SSE/写响应前由中间件设置 Set-Cookie,时序安全。
2. **前端:401 收敛到统一出口,覆盖 SSE/WS。** 新增 `sessionExpired()` 工具:跳 `/login?redirect=当前路径`(复用 http.ts 的单次跳转守卫),并 `clearSession()` 清 pinia 缓存。落点:
   - `http.ts` 现有 401 分支改走该工具;
   - SSE 连接(`api/runs.ts`、`api/servers.ts`、`api/containers.ts`、`ServiceLogViewer.vue`)与终端 WS(`ServerTerminal.vue`)的 `onerror/onclose` 处理:先探测一次 `/api/auth/session`,401 → 关闭连接并跳登录,否则维持现有重试/降级展示;
   - 等待中的请求保持 never-resolving,但视图可显示「会话已过期,正在跳转登录」。

## 二、会话有效期设计(响应上一轮反馈)

现状:7 天滑动续期,活跃用户不掉线。新增:

- **通过二步验证的正式会话(TOTP 验证码完成 / Passkey 登录)→ 30 天滑动**;未启用/未通过二步验证 → 维持 7 天;pending 中间态(密码已过、待验证码)→ 10 分钟固定,不滑动;
- 滑动续期按会话自身档位刷新(+30d / +7d),并触发上文 cookie 重发;
- 实现:`sessions` 加列 `mfa_state INTEGER NOT NULL DEFAULT 0`(0=普通 7 天;1=待二步验证 10 分钟;2=已过二步验证 30 天),存量会话不受影响;`Session` 暴露 `MFAPending`/`MFAVerified`。

## 三、其它核心设计决策

| 点 | new-api | 本方案 |
|---|---|---|
| MFA 配置 | DB settings + 管理页 | 同样走 `system_config` 表 + 设置页(新列),零 env、即时生效 |
| MFA 中间态 | cookie 会话存 pending_user_id | `sessions.mfa_state=1` 短会话,验证码通过后升级为 mfa_state=2 |
| TOTP 密钥存储 | 明文 | secretbox 加密:优先 vault(master key 已配),否则首用自动生成 32B 密钥存 `system_config.mfa_secret_key` |
| 备份码 | 4 个 bcrypt | 10 个 `xxxx-xxxx`,argon2id(复用 `auth.HashPassword/VerifyPassword`) |
| Passkey 数量 | 每用户 1 个 | 每用户多个(可命名设备) |
| WebAuthn 挑战 | cookie 会话 | `webauthn_challenges` 表 + 随机 id cookie(3 分钟、一次性) |
| 身份键 | int user id | 统一 `owner_key`:`"admin"` / `"user:<id>"`(即 WebAuthn user handle) |
| Passkey 登录 vs TOTP | Passkey 绕过 TOTP | 相同 |

## 六、后端:auth 与 httpapi 改造

1. `internal/auth/session.go`:`mfa_state` 三档 TTL、按档滑动、`Get` 返回刷新标记、`List` 过滤 pending。
2. `internal/auth/service.go`:`Login` 注入检查器接口(`TOTPEnabled(role, userID) bool`,mfa.Service 实现);密码通过且 TOTP 启用 → 建 mfa_state=1 会话;`CompleteMFA(token)` 升级为 mfa_state=2;Passkey 登录直接建 mfa_state=2。
3. `internal/httpapi/router.go`:`requireAuth` 按刷新标记重发 cookie(见第一节);pending 会话 → 401 + 错误码 `mfa_required`(`requireAuth` 与 `makeSessionHandler`);`makeLoginHandler` pending 时返回 `{"mfa_required": true}`。
4. 新文件 `internal/httpapi/mfa.go` 路由:
   - `/api/auth` 公开组:`POST /login/mfa`(pending 会话 cookie + CSRF + 验证码)、`POST /passkey/login/begin`、`POST /passkey/login/finish`、`GET /options`(`{passkey_login: bool}`)。
   - 受保护组:`GET /account/mfa`、`POST /account/mfa/totp/{setup,enable,disable,backup-codes}`、`POST /account/mfa/passkeys/register/{begin,finish}`、`DELETE /account/mfa/passkeys/{id}`。
   - requireAdmin 组:`DELETE /users/{id}/mfa/totp`、`DELETE /users/{id}/mfa/passkeys`;`GET /users` 附 `totpEnabled`/`passkeyCount`。
5. `internal/systemcfg/systemcfg.go` + `internal/httpapi/system_config.go`:`Config` 与 GET/PUT DTO 增加 `webauthnRpId`/`webauthnOrigins`/`passkeyLoginEnabled`(按需更新;`mfa_secret_key` 不经 API 暴露)。
6. `membergate.go` 白名单追加 `/api/account/mfa/*` 条目。
7. `internal/audit/audit.go`:新增 `totp_enabled`/`totp_disabled`/`backup_codes_regenerated`/`passkey_added`/`passkey_removed`/`member_mfa_reset`。
8. `cmd/pipewright/main.go`:装配 `mfa.NewService(db, sealer, systemcfg, lockout)` → `WithMFA`;auth 注入检查器;启动清理挑战。

## 运维说明

- 零配置可用(RP 自动推导);反代/多域名在「设置→系统」显式填写,即时生效;Passkey 需 HTTPS(localhost 除外);建议配置已有的 `PIPEWRIGHT_TRUST_PROXY` 正确识别 `X-Forwarded-Proto`。
- 唯一管理员同时丢失验证器与全部备份码时,恢复需直连 DB 删除 `totp_credentials` 行。
