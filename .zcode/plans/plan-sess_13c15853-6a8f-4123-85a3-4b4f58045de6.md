# 统一构建变量注入行为

## 目标语义(权威口径)

**规则一(脚本容器)**:凡执行用户脚本的隔离容器,env 注入序统一为:
运行参数 → 上游 job 输出(仅 DAG 同阶段有来源时)→ 流水线级构建变量(settings.Build.Vars,secret 经 vault.Reveal)→ 步骤自身 env(同名覆盖)→ `PIPEWRIGHT_ENV`(系统,末位)

**规则二(构建)**:凡执行 docker build / 工具链构建的地方(旧路径构建步骤、DAG build_image 节点,本地或远程),构建变量一律作为 `--build-arg` / 工具链 `-e` 注入(现状已实现于 `b.build`,只需补齐调用方)。

**规则三(非脚本节点)**:deploy_ssh / push_image / oss_upload / notify 不注入,保持现状。

优先级保持现状不改:步骤自身 env > 构建变量 > 上游 job 输出 > 运行参数(docker run 后出现的 `-e` 胜出)。

## 改动点

### 1. build_image 节点补构建变量(修缺口,含远程)
`internal/build/dag_stage_exec.go` `runBuildImageJob`(~:920):从节点 config 构造 `cfg` 后回填
```go
if settings != nil { cfg.Vars = settings.Build.Vars }
```
一处修复覆盖三条路径:本地串行、job 级 DAG(`runBuildImageJobIsolated`)、远程(`runBuildImageJobRemote` 经 `rb.runBuildImageJob` 复用)。

### 2. 旧单镜像路径自定义脚本步骤对齐
`internal/build/builder.go:344-359`:循环内执行前对副本 `cs` 追加(运行参数 → 构建变量 → 步骤自身 env):
```go
cs.Env = append(runParamsAsEnv(r.Trigger.Params), settings.Build.Vars...)
cs.Env = append(cs.Env, originalEnv...)
```
`runParamsAsEnv` 同包(`dag_stage_exec.go:1199`)可直接用。不引入 PIPEWRIGHT_ENV/captureStageEnv(阶段传值是 DAG 特性,超出本次统一范围)。

### 3. 阶段 post 步骤补构建变量
`internal/build/stage_post.go:23`:`runStagePost` 增加 `settings *pipeline.Settings` 参数;构造 post 步骤后追加
```go
step.Env = append(runParamsAsEnv(r.Trigger.Params), buildVars...)
```
两个调用点:
- `dag_stage_exec.go:387`:settings 已在作用域,直接传;
- `remote_stage_exec.go:525` `runLiftedStagePost`:把 `proj, _, perr := b.resolve(...)` 改为接收 settings 并传入(perr 失败分支已有,不用动)。
settings 为 nil 时跳过注入(防御)。post 无自身 env,不存在覆盖问题。

### 4. 权威口径注释收敛
- 在 `builder.go` `buildArgs`(~:535)上方写权威口径注释(两条规则 + 注入序 + 优先级);
- 修正各路径陈述不全/过时的注释引用同一口径:`dag_stage_exec.go:578-579`(漏了流水线级变量)、`remote_stage_exec.go:622`、`script_steps.go` 文件头、`stage_env.go:15-17`。

## 兼容性

- build_image 新收到 `--build-arg`:Dockerfile 未声明对应 ARG 仅产生 classic builder warning,不失败;存量流水线无感。
- 旧路径 script 步骤与 post 新增变量可见性:纯增量;同名冲突时步骤自身 env 仍胜出,无行为回退。
- secret 脱敏链路无需改动:`registerProjectSecrets`(httpapi/run_secrets.go:91-95)已把 Build.Vars secret 全局登记进 per-run Masker,三处注入均经 `buildArgs` Reveal、回显经 `maskKV` 打码。

## 明确不做

- 旧单镜像路径不引入 `$PIPEWRIGHT_ENV` 步骤间传值(DAG 特性,另立故事)。
- deploy/notify 的 `{{param}}` 模板不扩展 `{{var}}`。
- BuildKit `--secret` 替代 `--build-arg` 维持既有 deferred 记录。
