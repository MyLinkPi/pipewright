# Git 克隆支持 SSH 私钥认证

## 目标
`ssh_key` 凭据可用于 SSH 协议(`git@host:path` SCP 风格 / `ssh://git@host/path`)的私有 Git 仓库，覆盖全部 7 个克隆/探测入口；前端凭据下拉放开 ssh_key、可内联创建、URL 校验放行 ssh。

## 设计核心
认证选择矩阵（新工厂函数 `gitauth.TransportAuth`）：
| URL 协议 | 凭据类型 | 行为 |
|---|---|---|
| http(s) | git_token / git_http | 现有 BasicAuth 逻辑（不变） |
| http(s) | ssh_key / ssh_password | `ErrSchemeMismatch`（明确报错，不静默） |
| ssh | ssh_key | `ssh.ParsePrivateKey` → go-git `ssh.PublicKeys` |
| ssh | ssh_password | go-git `ssh.Password` |
| ssh | git_token / git_http | `ErrSchemeMismatch` |
| 任意 | 无凭据/secret 空 | nil（匿名，公开仓） |

SSH 用户名：URL user 段（`git@`）优先，其次凭据 username，留空由 go-git 默认 `git`。
Host key：`InsecureIgnoreHostKey`，与 `internal/target/ssh.go` 既有先例一致（同样的 nolint + DEFERRED known_hosts 注释）。

## 后端改动

### 1. `internal/vault/vault.go`
- `GitAuth{Username, Token}` → `GitAuth{Type, Username, Secret}`（Token 改名 Secret，语义涵盖 PEM/密码/token）
- `GetGitAuth` 的 SELECT 增加 type 列并填充

### 2. `internal/gitauth`（核心新代码）
- `TransportAuth(repoURL, credType, username, secret string) (transport.AuthMethod, error)`：按上方矩阵分流；http 分支内部复用现有 `BasicAuth`
- `ValidateRepoURL(rawURL string) error`：共享 SSRF 收口——http/https/**ssh** scheme + **SCP 风格**（无 scheme、`user@host:path`，冒号在首个斜杠前）；host 提取后沿用现有 blockedIP 策略（拒回环/链路本地/未指定，私网放行）
- `ErrSchemeMismatch` 哨兵错误
- `BasicAuth` 保留导出（签名不变）

### 3. 四份 SSRF 副本收敛（行为扩展为放行 ssh）
- `internal/build/cloner.go:112`、`internal/project/prober.go:79`、`internal/ai/analyze.go:348`、`internal/httpapi/source.go:226` 的 `validRepoURL`/`validateRepoURL`/`validSourceURL` 改为委托 `gitauth.ValidateRepoURL`（build 的 `IsRepoURLAllowed` 导出签名保留，repocache 不受影响）

### 4. 克隆契约从 `(username, token)` 改传 `vault.GitAuth`
机械替换以下全部接口/实现/调用点：
- `build.repoCloner` 接口 + `Cloner.Clone`（cloner.go:54）
- `repocache.Cache.Clone` + `ensureMirror` + `networkCloner` + `ListRefs`/`ListCommits` 及 lister 接口
- `builder.revealGitAuth`（builder.go:519，现返回值天然带 Type）及 4 处调用（builder.go:236、dag_stage_exec.go:188/487、remote_stage_exec.go:89）
- `project.RemoteProber` + `goGitProber.Probe`（prober.go:42）+ `service.probe`
- `ai.RepoAnalyzer.Analyze`、`ai.Differ.Diff/DiffCommit`
- `httpapi` source reader `cloneWorktree`、`pacloader.GitAuthRevealer` 接口（返回值改 `vault.GitAuth`）
- httpapi handlers：refs.go、ai_generate.go、run_diff.go、pac_preview.go
- 各处 `gitauth.BasicAuth(repoURL, username, token)` → `gitauth.TransportAuth(repoURL, a.Type, a.Username, a.Secret)`

### 5. 错误映射
- `prober.classifyProbeErr`：`gitauth.ErrSchemeMismatch` → `ErrCredentialError`（前端走既有 credential_error 分支，提示换凭据）
- 克隆侧 mismatch → 既有 `ErrCloneFailed`（probe 在创建时就会拦住）

## 测试与验证
- 新增 `internal/gitauth` 单测：TransportAuth 矩阵全分支（PEM 解析、Password、mismatch、空 secret）、ValidateRepoURL（ssh://、scp 风格、带端口、blocked IP、http 回归）
- 更新受签名影响的所有既有测试（go test ./... 全绿）
- `vue-tsc --noEmit` 通过
- 手动验证清单：用 git@gitee/gitea 私有仓创建项目（probe 通过）、触发构建、AI 分析、源码浏览、refs 列表——同一 ssh_key 凭据全链路可用

## 不做的事（明确排除）
- known_hosts/TOFU host key 存储（沿 target 包 DEFERRED 先例，注释标记）
- ssh_password 进入 Git 凭据下拉（后端 TransportAuth 已支持，仅 UI 不引导）
- git:// 协议支持
