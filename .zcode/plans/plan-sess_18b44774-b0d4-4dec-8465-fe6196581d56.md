# Ceph 集群部署 + 管理界面实现方案

## 总体设计

新增管理员功能域 `/ceph`:**部署向导**(cephadm 引导集群)+ **完整管理界面**(集群状态总览、主机/OSD、存储池、RBD 块设备、CephFS)。复用既有基座:

- SSH 执行:`internal/target.Service`(argv 数组纪律,凭据即用即弃)
- 后台任务:`internal/srcupdate` jobT 模式(互斥 + 步骤 + 日志环形缓冲 + 状态轮询)
- JSON 容错解析 + TTL 缓存:`internal/mesh/easytier/status.go` 的 pickStr/pickNum 模式
- 提权:`platformhttps/nginx_ops.go` buildPrivilege 模式(root 直跑 / `sudo -n` 前缀);仅支持 root/免密 sudo
- 凭据:vault 新增 `ceph_dashboard` 类型存自动生成的 dashboard 密码,复用既有 reveal 端点(带审计)

所有 `ceph`/`rbd` CLI 统一经 **bootstrap 主机**执行(部署时装 ceph-common,admin keyring 在 /etc/ceph),单一控制点。

## 后端

### 1. 新建 `internal/ceph/` 包

**ceph.go** — 模型 + Service:
- `Cluster{ID, Name, FSID, BootstrapServerID, Image, CephadmSource, PublicNetwork, ClusterNetwork, State, DashboardURL, DashboardUser, DashboardCredentialID, ...}`
- `HostSpec{ServerID, Roles, Labels, Devices []string}`
- `ClusterStatus{Health, HealthDetail[], Total/Used/AvailableBytes, MonCount, MgrCount, OsdUp, OsdIn, PGs}`
- `Pool{Name, Type(replicated/erasure), Size, ECProfile, PGNum, BytesUsed, QuotaMaxBytes, Apps[]}`
- `RBDImage{Pool, Name, SizeBytes, Provisioning, ParentSnapshot}`、`RBDSnapshot{Name, SizeBytes, Protected}`
- `Filesystem{Name, MetadataPool, DataPools[], MdsCount}`、`Subvolume{Name, Group, Path, BytesUsed}`
- `DeployStatus{Running, Step, Message, Done, Error, Log[]}`(srcupdate 同形)
- Service(按域分组):
  - 集群:`ListClusters / GetCluster / CreateCluster / DeleteCluster(仅解除纳管) / StartDeploy / DeployStatus / ClusterStatus`
  - 主机/OSD:`ListHosts / AddHost / RemoveHost(drain+rm) / ListOSDs / AddOSD / RemoveOSD(out+迁移+purge)`
  - Pool:`ListPools / CreatePool / UpdatePool(配额/副本数) / DeletePool`
  - RBD:`ListImages / CreateImage / ResizeImage / DeleteImage / ListSnapshots / CreateSnapshot / DeleteSnapshot / RollbackSnapshot`
  - CephFS:`ListFilesystems / ListSubvolumes / CreateSubvolume / DeleteSubvolume`
  - 名称类入参(池/镜像/快照/设备路径等)一律白名单正则校验(如 `^[a-zA-Z0-9][a-zA-Z0-9_.-]*$`)后再进 argv

**exec.go** — SSH 执行抽象(接口注入,fake 可测):提权探测(`id -u`=0 或 `sudo -n true`,否则含 sudoers 指引的 ErrNoPrivilege)、`runJSON`(`-f json` 容错解析)、单命令超时(默认 5 分钟)。

**bootstrap.go** — 部署管线(每集群互斥 ErrBusy,日志环形缓冲 ~500 行):
1. `preflight`:逐台 SSH 连通、提权探测、docker/podman、systemd、python3、lvm2、hostname 唯一、`lsblk` 校验 OSD 设备存在且无文件系统、时间同步(仅告警)
2. `install`:每台装 cephadm(apt/dnf 包优先,否则 download.ceph.com 脚本下载落地执行;`CephadmSource` 可配镜像)
3. `bootstrap`:首主机 `cephadm bootstrap --initial-mon-ip --initial-dashboard-user/password`(密码自动生成入 vault;短暂出现在远端 argv,私有环境可接受);解析 fsid;装 ceph-common
4. `hosts`:`ceph orch host add <hostname> <addr> <labels>`
5. `osds`:`ceph orch daemon add osd <host>:<device>`
6. `verify`:轮询 `ceph -s` 至健康;从 `ceph mgr services` 记录 dashboard URL

命令依据:`ceph osd pool *`、`rbd *`(ceph-common 自带)、`ceph fs subvolume *`。

**store.go** — 参数化 SQL 双方言;**ceph_test.go** — fake executor 单测(命令拼装、校验分支、JSON 解析、互斥)。

### 2. 迁移 `0082_ceph_clusters.sql`(sqlite + mysql 各一)

表:`ceph_clusters`(配置 + vault 引用,无明文)、`ceph_hosts`(cluster_id+server_id 主键,roles/labels/devices)、`ceph_osds`(部署意图 + osd_id/状态回填)。Pool/RBD/CephFS 为实时查询,不建表。

### 3. HTTP API:`internal/httpapi/ceph.go` + `router.go`

`Option WithCeph`;挂 `requireAdmin` 组(member 默认拒绝),写方法过 CSRF + 审计:

- 集群:`GET/POST /api/ceph/clusters`;`GET/DELETE /api/ceph/clusters/{id}`;`POST .../deploy`(202,忙 409);`GET .../deploy/status`;`GET .../status`(TTL 15s)
- 主机/OSD:`GET/POST .../hosts`;`DELETE .../hosts/{serverId}`;`GET/POST .../osds`;`DELETE .../osds/{osdId}`
- Pool:`GET/POST .../pools`;`PATCH/DELETE .../pools/{name}`
- RBD:`GET/POST .../pools/{name}/images`;`PATCH/DELETE .../pools/{name}/images/{image}`;`GET/POST .../images/{image}/snapshots`;`DELETE .../snapshots/{snap}`;`POST .../snapshots/{snap}/rollback`
- CephFS:`GET .../filesystems`;`GET/POST/DELETE .../filesystems/{fs}/subvolumes`

`internal/vault/vault.go` 增 `TypeCephDashboard = "ceph_dashboard"`(单串,掩码全点)。

### 4. `cmd/pipewright/main.go` 装配

`cephSvc := ceph.New(st.DB, targetSvc, credVault)`(deploySvc 附近);`httpapi.New(...)` 追加 `httpapi.WithCeph(cephSvc)`。

## 前端(Vue 3 + naive-ui)

### 5. `web/src/api/ceph.ts` — 全部端点的类型化封装(mesh.ts 模式)

### 6. 页面

**`web/src/views/Ceph.vue`**(集群列表 + 创建向导):
- 集群卡片:名称/fsid/健康徽标/状态;空态引导
- 创建向导 3 步:① 基本信息(名称、ceph 镜像默认值、cephadm 安装来源、public/cluster 网段)② 选主机(服务器多选、指定 bootstrap 主机、每台角色与 OSD 设备路径)③ 确认(说明 dashboard 密码自动生成入保险库)

**`web/src/views/CephClusterDetail.vue`**(管理界面,Tab 页):
1. **总览**:健康徽标(OK/WARN/ERR)、容量条(总/用/可用)、mon/mgr/osd 计数、PG 状态、近期告警事件(`ceph health detail -f json`),15s 轮询
2. **主机**:表格(主机名/地址/角色/标签/状态)+ 添加主机弹窗 + 移除(二次确认,提示 drain 数据迁移)
3. **OSD**:表格(id/主机/设备/up/in/用量)+ 添加表单(主机+设备路径)+ 移除(二次确认)
4. **存储池**:表格(名称/类型 replicated|EC/副本数/PG 数/用量/配额/应用标签)+ 创建弹窗(名称、PG 数、副本或 EC)+ 编辑配额/副本数 + 删除(强确认)
5. **块设备**:按池筛选的镜像表(名称/容量/精简配置/父快照)+ 创建(池/名称/大小 GB)+ 扩容 + 删除;快照子面板(列表/创建/删除/回滚,回滚强确认)
6. **文件系统**:fs 卡片(名称/元数据池/数据池/MDS 数)+ 子卷表(名称/路径/用量,路径可复制供客户端挂载)+ 创建/删除子卷
7. **部署日志**:部署进行中显示步骤进度 + 日志流(3s 轮询);dashboard 链接 + 密码查看(凭据 reveal)

### 7. 路由与导航

`web/src/router/index.ts`:`/ceph`(列表,admin)、`/ceph/:id`(详情,admin);`AppShell.vue` adminNavItems 增 `nav.ceph`(cluster 旁)。

### 8. i18n

新命名空间 `ceph.ts` × 8 locale;`nav.ceph` 加入 nav 键所在命名空间 × 8;过 keyParity / componentKeys 测试。
