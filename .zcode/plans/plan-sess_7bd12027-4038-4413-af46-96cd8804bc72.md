# 多节点构建机池 + 标签调度（FR-8-14 续）

## 形态（已确认）
- **不引入守护进程**：构建机 = 打了标签的已登记服务器（`target.Server`），派发仍走现有 SSH 通道（控制机克隆 → tar.gz 上传 → 远程容器执行）。token 全程只在控制机。
- **双层选择器**：项目级默认选择器 + 单 stage 可覆盖。
- **调度三要素**：标签匹配 → 优先级 → 流水线亲和。

## 1. 数据模型 — 迁移（sqlite + mysql 双镜像；实际落为 0052，0049 已被占用）
`internal/store/migrations/{sqlite,mysql}/0052_runner_pool.sql`：
- `ALTER TABLE servers ADD COLUMN labels TEXT NOT NULL DEFAULT ''` — 逗号分隔标签项（纯 tag 如 `linux`，或 `k=v` 如 `arch=arm64`）。**未打标签的服务器永远不会被选中**（空标签不匹配任何选择器），无需单独的"启用构建机"开关。
- `ALTER TABLE servers ADD COLUMN max_builds INTEGER NOT NULL DEFAULT 1` — 每机并发槽位（0 = 用全局默认，全局默认 **1**）。
- `ALTER TABLE servers ADD COLUMN priority INTEGER NOT NULL DEFAULT 0` — 调度优先级，**数值越大越优先**（0-100）。
- `ALTER TABLE project_runners ADD COLUMN selector TEXT NOT NULL DEFAULT ''`，回填 `UPDATE project_runners SET selector='server:'||runner_server_id WHERE runner_server_id<>''`（MySQL 用 CONCAT）。旧列保留不删，读取以 selector 为准。

**选择器语法**（AND 语义，无 OR/取反）：`server:<id>` 钉死单机（兼容旧行为）；`linux,arch=arm64` 全项匹配才命中。

## 2. 领域层 — internal/runner 扩展
- `selector.go`：`ParseSelector` / `MatchSelector` 纯函数 + 表驱动测试；非法语法返回错误（供 API 层 422）。
- `scheduler.go`：新 `Scheduler`（与现有配置 `Service` 并列，不改其冻结签名）：
  - 直查 `SELECT id,name,labels,max_builds,priority FROM servers`（沿用本包"不直依赖 target"的既有设计）。
  - **选机算法** `Acquire(ctx, pipelineID, selector, log) (serverID, release func(), err)`：
    1. 标签匹配得候选集；
    2. 健康探测过滤（注入 `HealthProber` 接口，main.go 用 target.Service 适配，同 `targetExister` 模式；可达缓存 5min，不可达缓存 30s）；
    3. 取**有空闲槽位**的子集，按 **priority 降序 → 本流水线最近使用过的机器优先（亲和）→ in-flight 升序 → 名称**排序，依序非阻塞抢槽；
    4. 全忙 → 进 FIFO 等待队列，任一槽位释放时唤醒重跑第 3 步（亲和机若已忙则用其他空闲机，不空等）；ctx 取消可中断（run 取消/中止）。
  - **亲和性**：调度器内存维护 `map[流水线ID]最近使用机器`（acquire 成功即更新），同优先级空闲机中优先复用 → 命中远程机 docker 镜像层缓存，省拉取。内存态、重启即失（语义本就是"最近"，不做持久化）。
  - 错误：`ErrNoRunnerMatch`（标签无命中）、`ErrNoRunnerAvailable`（命中但全不可达），阶段失败日志明示原因。
- 现有 `Service` 增读 selector（`SelectorFor`），`Save` 扩为收 selector；`server:<id>` 校验机器存在。
- 全局默认槽位 `PIPEWRIGHT_RUNNER_SLOTS`（**默认 1**），解析沿用 main.go:464-474 模式。
- run 级准入闸门（pool.go 全局/项目计数）**不动**；机器维度在阶段执行器层 acquire/release 约束。

## 3. 派发点改造 — internal/build/remote_stage_exec.go
- `RunnerLookup` 接口升级为 `RunnerResolver`：`SelectorFor(ctx, projectID)` + `Acquire(...)`（内部接口，同步改 main.go 接线与 fake 测试）。
- `NewStageExecutorWithRunner` 分支（现 :51）：`effectiveSelector = stage.Runner 非空 ? stage.Runner : 项目选择器`；非空则 `acquire → runStageRemote → defer release`。同 run 的并行 stage 各自独立选机（工作区本就按 run+stage 隔离）。
- `remote.go`：`NewRemoteDriver` 写死 "docker" 改为**远程 CLI 探测**（`sh -c 'command -v nerdctl || docker || podman'` 经现有 `RemoteExecer`，内存 TTL 缓存），支持异构 nerdctl/podman 构建机。
