# 集群设计 v2：对等节点 + EasyTier 自组网

## 0. 概念变更与摘要

- **去掉中心节点**：集群 = 一组**对等（peer）pipewright 节点** + 一个 EasyTier 虚拟网络；无环境/中心之分，每节点本地自治（自己的库、项目、服务器、权限）。原"环境"概念取消，统一称**节点**。
- **网络层集成 EasyTier**（去中心化 mesh VPN，WireGuard 加密，打洞优先 + 中继兜底）：节点间所有 pipewright API 通信走 EasyTier 虚拟 IP，集群页可查看每条链路是 **p2p 直连还是 relay(哪个中继节点)**、延迟/丢包。
- **权限默认全拒绝**：每节点本地配置三张 ACL——①可见（对其开放我的服务器/项目/运行状态）②允许推送产物/镜像 ③允许触发我的工作流；默认均为空=拒绝。③是对你两条权限的补充（"启动节点工作流"是执行类动作，不宜隐含在读权限里），如想并入①可在评审时去掉。
- 保留上版已确认的产物语义：镜像以 docker save 归档传输（通道改为 mesh 直传）；接收端"被推送源"项目、自动创建与一一对应、部署时选择修订/条目的设计全部沿用（对应键改为 来源节点+来源项目）。

## 1. EasyTier 集成（新包 `internal/mesh/easytier`）

- **两种模式**：
  - **托管模式（默认）**：pipewright 管理 `easytier-core` 子进程——二进制按需下载（复用 `system_config.release_mirror` 机制 + checksum 校验）或使用运维手工放置的路径；由 mesh 设置生成参数（`--network-name/--network-secret`、`-i` 静态虚拟 IP 或 `--dhcp`、`-l` 监听、`-p` peers、`-r 127.0.0.1:15888` 固定 RPC portal），带退避的监督重启。子进程聚合使用，规避 LGPL-3.0 传染（不修改、不链接其代码），随附许可声明。
  - **外部模式**：运维自跑 EasyTier，pipewright 只读其 RPC portal（填写地址即可）。
- **状态查询**：周期调用 `easytier-cli --rpc-portal 127.0.0.1:15888 peer/route/node --output json`（白名单子进程调用，同"SSH 静态命令"哲学），解析出：每 peer 的虚拟 IP/hostname/版本/`lat_ms`/`loss_rate`/rx/tx/`tunnel`（`p2p` 或 `relay(节点id)` 即"走没走转发、转发节点是谁"）；`route` 的 `next_hop_ipv4` 交叉验证路径。TTL 缓存 + stale-while-revalidate（对齐 a1f676b 模式，~10s）。
- **部署注意**：docker 镜像多阶段 COPY 官方 `easytier/easytier` 镜像内二进制，compose 需 `/dev/net/tun` + NET_ADMIN；Windows 需管理员 + wintun（文档注明）。
- 新节点加入：配置网络名/密钥 + 至少一个 peer URL（指向网内任一节点或社区共享节点）→ EasyTier 自动组网 → 应用层发现接管。

## 2. 节点身份、发现与鉴权（`internal/mesh`）

- **身份**：每节点首启生成 UUID + **ed25519 密钥对**（私钥入 vault，公钥随 hello 发布）。node_id 是 ACL 与对应关系的锚点。
- **发现**：后台循环 = EasyTier peer 列表（虚拟 IP）→ 逐个探测 `GET http://<vip>:<api端口>/api/mesh/hello`（默认 api 端口可配，手工补录兜底）→ upsert `mesh_peers`（node_id、名称、虚拟 IP、公钥、版本、last_seen、在线状态）。公钥 TOFU 缓存，变更告警。
- **请求鉴权**：节点间请求带 `X-PW-Node: <node_id>` + `X-PW-Timestamp` + `X-PW-Signature`（ed25519 签名 method/path/body-sha256/timestamp），接收方查公钥验签 + 时间窗防重放。`/api/mesh/*` 豁免 session/CSRF（同 webhook 先例），新增 `meshAuth` 中间件；验签通过≠放行，还要过 ACL。网络层另有 network-secret + WireGuard 加密，双层防御。

## 3. 权限模型（每节点本地，默认全拒绝）

| ACL | 控制内容 | 默认 |
|---|---|---|
| `visible_to` | 对方能否查询我的**服务器指标、项目列表/详情、运行状态**，以及在集群页展开我的数据 | 空 |
| `push_allowed` | 对方能否向我**推送产物/镜像**（触发自动建项目/新修订） | 空 |
| `trigger_allowed` | 对方能否**启动我的工作流** | 空 |

- ACL 配置在**接收方**（"我的资源给谁看"），UI 是 mesh_peers 多选；被拒请求返回 403，调用方 UI 显示"未授权"占位。
- 推送隐含需要读（确认目标项目），实现上 push 权限单独判定、不要求 visible。

## 4. 数据模型（迁移 0077–0080，sqlite/mysql 双份，所有节点同 schema）

| 迁移 | 表/列 | 说明 |
|---|---|---|
| 0077 | `mesh_settings`（单行：node_id、名称、密钥引用、easytier 模式/配置 JSON、api 广播端口） | 本节点身份与组网配置 |
| 0077 | `mesh_peers`（node_id UNIQUE、名称、virtual_ip、api_port、public_key、version、last_seen、来源 auto/manual） | 已知节点注册表 |
| 0077 | `mesh_acl`（单行：visible_to/push_allowed/trigger_allowed JSON 数组） | 三张 ACL |

## 5. 节点间 API（`internal/httpapi/mesh_inbound.go`，签名鉴权 + ACL）

- `GET /api/mesh/hello` → {node_id, 名称, 版本, public_key}（发现握手）
- `GET /api/mesh/servers/metrics`（visible）
- `GET /api/mesh/projects`、`GET /api/mesh/projects/{id}`（含参数 schema、流水线就绪标志）（visible）
- `GET /api/mesh/projects/{id}/runs?limit=`（visible）
- `POST /api/mesh/push`（push_allowed）：multipart/流式——manifest（origin{node_id, project_id, name}、revision_label、items[{name, kind file|image, sha256, size, dest_name, image_ref}]）+ 逐 blob 流；接收端 sha256 校验、按 origin 幂等定位/自动创建项目、file 入本机 artifactstore（去重）、image 归档 `docker load` 后推入本机 registryhub；同步返回 {project_id, revision_id, items}。
- `POST /api/mesh/projects/{id}/runs`（trigger_allowed）{params, revision?} → {run_id, run_path}（新 TriggerType `mesh`，审计记录来源节点）
- `GET /api/mesh/runs/{id}/events`（trigger_allowed，SSE）→ 供发起方回传日志/状态。
- 本节点管理面（admin session）：`/api/mesh/peers`、`/api/mesh/acl`、`/api/mesh/easytier/{status,config}`、`/api/mesh/overview`（聚合本机视角：peers + EasyTier 链路 + 各 peer 可见性探测结果）。

## 6. 流水线节点（每个节点可用，`internal/build/mesh_push.go`、`mesh_trigger.go`）

接线沿用 push_image/oss_upload 样板：dag_stage_exec.go 分类分组 + job 级 DAG switch 双路径；不入 remote runner（`runnerJobsOf`）；Builder 加 `WithMeshClient/WithMeshPeers` 最小接口；校验器挂 normalizeSpec 钩子（环境→节点存在性校验放 pipeline_validation 端点）；ai/catalog.go 登记；前端 jobConfigSchema + JobTypeIcon + 全部语言包。

- **mesh_push（推送产物/镜像到节点）**：字段 = 目标节点选择器（新 field kind `meshNode`）、条目结构化编辑器（`envItems`：上游产物/镜像 + 目标名，多选）、revisionLabel（{{branch}}/{{commit}}/{{date}}/{{runId}} 占位）、timeoutMinutes。执行：目标离线（EasyTier peer 缺席或 hello 失败）快速失败 → 收集产物（artifactstore 直读）/镜像（docker save 导出，按 ref 缓存）→ 流式上传 → 回显对方日志与 {对方项目, 修订号}。
- **mesh_trigger（启动节点工作流）**：字段 = 目标节点、远端项目（依赖目标节点联动拉取对方 `/api/mesh/projects`）、params（KV，schema 来自对方）、waitForCompletion（默认开）+ timeoutMinutes。执行：建远端 run → 拿 run_path 打深链 → 订阅对方 SSE 回流步骤状态/日志到本节点 → 终态映射成败；关闭等待则创建即完成。

## 7. 接收端："被推送的产物/镜像"源项目

- `source_type='pushed'` 项目仅由推送自动创建（V1 不开放手建，保证对应完整）；名称取来源项目名（冲突加后缀），`UNIQUE(origin_node_id, origin_project_ref)` 幂等；被删后下次推送按 origin 重建。
- 流水线不变式（pipeline.go:542-550）：仍恰一个 source 阶段；source job 类型随项目源类型限定 `git_source | pushed_source`；fillSourceDefaults 分支；pushed 项目禁用 webhook/cron。
- **物化**：阶段级克隆（dag_stage_exec.go:211）与 DAG 路径 `cloneJobWorkspace`（:546）按 source_type 分支——解析修订（运行指定或最新）→ file 条目按 workspacePath 恢复进工作区（同 restorePriorArtifacts）、commitTag 取修订 label；`pushed_source` 节点把各条目 EmitArtifact（file→带 workspacePath；image→`Type:"image"`、Reference=本机 registry ref），下游 deploy_ssh/deploy_container 沿既有 artifactJob/artifactName 绑定消费，**部署链路零改动**。
- **部署时选择**：手动运行接口为 pushed 项目增加 `revision` + `items` 字段（run.Trigger 增类型化字段），运行对话框展示修订选择器（默认最新）+ 条目多选；mesh_trigger 触发也可带 revision（缺省最新）。

## 8. 前端（web/）

- **集群页** `views/Cluster.vue`：节点卡片列表（名称/虚拟 IP/版本/在线/本机视角链路状态：`p2p` 或 `经 X 中继`、延迟/丢包/流量）+ EasyTier 全局面板（本机虚拟 IP、网络名、peers 数、TUN/子进程健康）+ 每节点可展开：服务器指标（授权可见时，复用 ServerMetricsCard 数据结构）、运行统计与近期流水线（可见时）；未授权显示占位徽标。轮询 `/api/mesh/overview`（15s，仿 ServerStatus.vue）。
- **设置**：`settings/SettingsMesh.vue`——节点身份（名称）、EasyTier 配置（模式/网络名/密钥/虚拟 IP/peers/托管二进制状态）、三张 ACL 编辑器（peer 多选）、已知节点管理（手工补录/重命名）。
- **编辑器**：jobConfigSchema 新增类别 cluster + `mesh_push`/`mesh_trigger` spec；JobDrawer 新控件（meshNode 联动 memberProject 同款依赖取选项）、JobTypeIcon、PICKABLE_TYPES；`pushed_source` spec。
- **项目页**：源类型徽标、origin 只读展示；手动运行修订/条目选择；RunDetail 触发来源徽标（远端节点触发）。
- i18n 全部 9 个语言包补 key（过 parity 测试）。

- env vars：`PIPEWRIGHT_MESH_API_PORT`（对外广播端口，默认取 `PIPEWRIGHT_ADDR`）、`PIPEWRIGHT_EASYTIER_BIN`（手工放置路径，缺省按需下载）、`PIPEWRIGHT_EASYTIER_MODE=managed|external`；网络名/密钥等在设置页配置存库（密钥 vault 加密）。
- main.go：mesh 设置存在且启用 → 启动 easytier 监督器 + 发现循环；mesh client/service 注入 httpapi 与 Builder。
- README 补集群章节；compose 示例加 tun 权限注释。

## 10. 失败语义

- 目标节点离线（EasyTier 无该 peer / hello 失败）：节点快速失败并给明确日志。
- 上传中断：blob sha256 内容寻址天然幂等，重跑只补缺；接收端中止导入无害。
- SSE 断开：mesh_trigger 降级轮询远端 run 状态（3s，仿 subscribeRunEvents 降级）。
- 超时：节点失败；取消：HTTP 断开即传播（ctx cancel），接收端中止。
- 公钥变更/验签失败：拒绝 + 审计告警。

## 11. 安全与合规

- 双层：EasyTier network-secret + WireGuard/AES-GCM（网络层）× 节点密钥签名 + ACL（应用层），默认全拒绝；签名防重放（时间窗）；密钥/密文不落日志（masker）；审计事件：ACL 变更、授权拒绝、推送/触发、自动建项目。EasyTier 以未修改子进程聚合使用（LGPL-3.0 合规），发布物附其许可证文本。

## 12. 实施里程碑

1. **mesh 基座**：迁移 + internal/mesh（身份/发现/ACL/签名中间件）+ easytier 监督器与状态解析 + 管理面 API + 设置页。
2. **接收端推送源**：/api/mesh/push（自动建项目/blob 校验去重/镜像导入 registryhub/修订）+ 克隆分支物化 + pushed_source 节点 + 手动运行选择 UI + 项目页徽标。
3. **两个流水线节点**：mesh_push/mesh_trigger 执行器与双路径接线 + 校验器 + AI 目录 + 编辑器 schema/控件/图标/i18n。
4. **集群页**：overview 聚合 + 节点链路状态 + 可见数据展开 + 未授权占位。
5. **收尾**：审计、失败/取消/超时边界、README、测试补全。

## 13. 测试要点

签名验签与防重放；ACL 三权限独立判定与默认拒绝；发现 upsert 与公钥变更告警；push 幂等（同 hash 去重、同 origin 复用项目、重名后缀）；pushed 项目源不变式（配 git_source 报错等）；easytier CLI JSON 解析（含 relay(节点) 字段）；httptest 双节点走通 hello→push→trigger→SSE 回流；前端 locale parity。
