# 服务注册与网关集群化彻底改造

## 目标架构（一句话）

服务注册从「网关本机容器 + 共享 docker 网络」改为**集群级宿主端口模型**：每个注册实例 =（服务, 服务器, 宿主端口），容器实例的宿主端口由部署时**范围探测自动分配**，网关（nginx）对**全部网关主机**渲染同一份配置、按 `服务器地址:端口` 反代**集群所有实例**（本机没部署也能代理）；健康检查用户只填 path，端口自动推导；部署节点内选基域 + 填服务名**一键生成**注册绑定；部署后实例表与实际拓扑**自动同步清理**。

## 单机升级语义：两条刻意不同的路径

统一实例池之上，容器与非容器走**不同的单机升级语义**：

1. **容器实例 = 扩容升级缩容（maxSurge 轮转，零停机）**
   扩容（同机起新容器、自动分配新宿主端口，旧容器继续服务）→ 新实例预热健康 → upstream 原子切换（old 出、new 进，一次 reload）→ 排空窗口 → 缩容（停旧容器）。全程新旧并存，本机任何时刻都有实例在线；失败只删新容器，旧实例未动、天然无需回滚。

2. **非容器实例 = 本机摘挂（短暂下线窗口）**
   非容器进程无法同机双实例共存（端口/进程模型只能原地升级），故走：摘除（本机实例退出 upstream）→ 升级（发布目录软链切换 + 重启命令 / 命令部署）→ 健康门控 → 挂回。本机在升级窗口内不接流量，**集群可用性由其余机器的实例保证**——滚动批次编排（默认首批 1 台）确保绝不会把一个服务的全部实例同时摘掉；部署失败保持摘除不回流量。

## 1. 数据模型与迁移（internal/servicereg + migrations）

- 新迁移 `0068`（sqlite + mysql 同步）：
  - `service_reg_instances` 新增 `server_id TEXT NOT NULL DEFAULT ''`、`host_port INTEGER NOT NULL DEFAULT 0`（网关反代用的宿主端口；容器实例=自动分配端口，非容器实例=进程端口）。
  - 唯一约束 `(service_id, container)` → `(service_id, server_id, container)`；非容器实例 `container=''`。
- `Instance` 结构体（instance.go:14）扩为 `{ServerID, Container(可空), Port(容器内/服务端口), HostPort, Attached}`；`EffectiveHostPort` = HostPort>0 ? HostPort : Port。
- `RegisteredService.UpstreamKind` 保留但弱化为「实例来源默认」：手动 address 单上游服务继续走现有变量+resolver 路径不变；部署托管服务（容器与非容器）统一走实例池。
- 存量迁移：现有实例 `server_id=''` → 渲染时跳过并写入 `last_apply_errors` 提示「待下次部署自动补齐」；下次部署按容器名匹配 upsert 补齐。

## 2. 网关集群化渲染（nginx.go / servicereg.go）

- `renderNginxConf` 新增 `serverAddr map[string]string` 入参；upstream 成员从 `inst.Container:port` 改为 `addr(inst.ServerID):EffectiveHostPort`。
- 删除 `applyWithServer` 中「仅渲染本机存活容器」的剔除逻辑（containerAlive 降级为可选告警，故障实例交给 `max_fails=2 fail_timeout=10s` 熔断）——所有网关主机渲染并推送**同一份**全量配置，本机无实例也能代理远端。
- 服务器地址解析：`servicereg` 新增 `ServerAddrFunc(serverID) (string, error)` 由 main.go 注入（target 服务取 SSH Host；主机名由控制端 `net.LookupHost` 解析为 IP 后写入，避免 upstream 静态成员解析失败导致 `nginx -t` 卡死 apply）；解析失败的实例跳过 + 记入 last_apply_errors。
- `connectUpstream`（docker network connect 实例）停用——实例不再依赖共享网络；网关容器自身仍按现有 settings 运行（向后兼容不动）。
- TCP 服务维持现状（单上游 address 可跨机），不纳入本次实例池改造。

## 3. 实例反查与 Swap 重写（instance.go）

- `ResolveDeployInstances`：去掉 `st.HasServer(serverID)` 门槛（任何部署目标机都可有实例）；匹配顺序 ①精确 `serviceID`（部署节点绑定）②实例容器名 ③服务名（存量兼容）；**只返回该 serverID 上的 attached 实例**（滚动升级只动本机，不能摘别的机器）；非容器实例（container=''）同样可匹配返回（`DeployInstance` 增 `ServerID/HostPort`，`Container` 可空）。
- `SwapInstance(serviceID, oldContainer, newContainer, hostPort)`：容器轮转（扩缩容路径）改名时同步更新 `host_port`，apply 失败整体回滚。
- 新增 `EnsureInstance(serviceID, serverID, container string, port, hostPort int) (*Instance, error)`：部署时 upsert（存在即更新端口/attached，不存在即创建）。
- 新增 `PruneInstancesNotIn(ctx, serviceID string, serverIDs []string)`：部署成功后同步清理不再覆盖的实例（用户已选「自动同步清理」）。

## 4. 容器部署：端口范围探测自动分配（internal/deploy）

- `ports` 配置语法扩展（`imageRunArgs`，image_release.go:50）：`8080` 或 `auto:8080` = 仅容器端口、宿主端口自动分配；`8080:80` 显式映射（兼容现状）。新增 cfg `autoPortRange`（默认 `20000-30000`，部署节点可覆盖）。
- 分配实现：候选端口在目标机 `bash -c 'exec 3<>/dev/tcp/127.0.0.1/<p>'` 探测（连接成功=占用，失败=空闲），首个空闲者用之；`docker run` 报 "port is already allocated" 时兜底换下一候选重试（docker 是最终仲裁者）。实际映射写入部署日志与结果 message。
- `deployInstanceRollingOne` / `rollOneInstance`（扩缩容路径）：删除现有 `-p` 端口冲突报错提示逻辑（instance_rolling.go:142-146）——新模型下发布宿主端口是常态；每实例容器各自分配宿主端口；预热探测保留容器 IP:容器端口方案（不依赖映射）；Swap 时上报新 host_port。
- 旧容器无 `-p` 的存量：下次部署重建时自动分配宿主端口（统一模型迁移）。

## 5. 健康检查：只填 path，端口自动推导（deploy/healthcheck.go + deploy.go:612）

- 端口解析链（`healthCheckFromCfg` 调整为部署期解析，时序在端口分配之后）：
  1. 显式 `healthPort`（高级覆盖，保留）；
  2. 容器部署 = 自动分配/显式映射得到的**第一个宿主端口**，URL 自动拼 `http://127.0.0.1:<hostPort><path>`；
  3. 非容器部署 + 配了服务注册 = `regPort`；
  4. 其余无端口可推导 → 维持现状要求 healthPort / healthCommand。
- 前端表单主推「探测路径 path」，`healthPort` 降级为高级字段。

- 后端新 API：`POST /api/servicereg/services/ensure`（幂等：`{domainId, name, upstreamKind, upstreamPort}` → 存在即复用/更新并返回 service + FQDN）。
- 部署节点 job config 新键：`regServiceId`（一键生成回填）、`regPort`（非容器服务端口；容器服务端口由 ports 推导）、`autoPortRange`；`internal/build/dag_stage_exec.go` passthrough 清单增补这三个键。
- 前端 `jobConfigSchema.ts`：
  - `DEPLOY_CONTAINER_FIELDS`：新增「服务注册」区——基域下拉（新控件 `apiSelect`，拉取 `/api/servicereg/domains`）+ 服务名 + 「一键生成」按钮（新控件 `generate`，调 ensure API 后回填 regServiceId 并展示 FQDN 预览/解绑）；`ports` 字段提示新语法（自动分配）。
  - `DEPLOY_SSH_FIELDS`：同样区域 + `regPort` 端口字段；非容器部署配了 regServiceId 即走本机摘挂路径。
  - `JobDrawer.vue` 实现两个新控件；i18n 9 语言（pipelineJob.ts / serviceReg.ts）补键，过 keyParity 测试。
- 部署期联动（`DeployForStage`）：regServiceId 存在时，部署前按目标机 upsert 实例行；部署成功后更新 host_port 并置 attached；**全部目标成功后**调用 `PruneInstancesNotIn` 清理该服务下不再属于本次目标集合的实例（部分失败/重试时不清）。

## 风险与说明

- **网络前提**：网关到所有服务器的宿主端口必须可达（防火墙放行 autoPortRange 段），文档中明示。
- **存量破坏面**：统一模型后，依赖共享网络且无 `-p` 的存量服务在下次部署时强制重建为宿主端口模式（用户已确认彻底切换）；手动 address 单上游服务不受影响。
- 端口探测依赖目标机 bash（`/dev/tcp`）；docker 报错重试兜底，两者都不可用时显式失败并提示人工指定映射。
