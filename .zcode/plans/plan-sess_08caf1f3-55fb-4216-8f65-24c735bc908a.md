# SSH 多跳登录(跳板链)实现计划

目标:服务器支持任意顺序的跳板链(手动逐跳填写主机/端口/用户/凭据,每跳独立选择 ssh_key/ssh_password 凭据,≤5 跳)。跳板链对**所有**走 target.Service 的操作自动生效(部署、文件上传、容器终端、日志流、远程构建、docker login、连通测试),因为 main.go 单点注入一个 targetSvc。

## 1. 后端领域层 — `internal/target/target.go`

- 新类型 `ServerJump{Host, Port, User, CredentialID}`;`Server.Jumps []ServerJump`(持久化为 `servers.jumps` JSON 列,空=`[]`)。
- `CreateInput.Jumps []ServerJump`;`UpdateInput.Jumps *[]ServerJump`(nil=不改,非 nil=整体替换)。
- `SSHConfig` 追加 `Jumps []JumpConfig`(`JumpConfig{Addr, User, PrivateKey, Password}`)——**SSHDialer 接口签名不变**,所有现有 fake dialer 与上游包(deploy/build/httpapi 等)零改动,仅真 sshDialer 消费 Jumps。
- 新 sentinel `ErrInvalidJump`;`validateJumps`(每跳 host/user/credentialId 必填、端口 1..65535、≤5 跳)+ `validateJumpCredentials`(仿 `validateSudoCredential` target.go:294:vault.Exists + 查 credentials.type ∈ {ssh_key, ssh_password},类型错配复用 `ErrCredentialTypeMismatch`)。
- 抽公共 `resolveSSHConfig(srv)`:主凭据 + 每跳凭据经 `vault.Get` 解析明文(looksLikePEM 分流),替换 run/Upload/DockerLogin/ExecStream/ExecInteractive **5 处重复**取凭据段;清理统一走 `wipeSSHConfig(&cfg)`(含各跳明文)。
- Create/Update 的 INSERT/SELECT/scanServer/合并逻辑加 jumps 列(JSON 序列化/反序列化)。

## 2. 后端拨号链 — `internal/target/ssh.go`

- 抽公共 `dialClient(ctx, addr, cfg) (*ssh.Client, func(), error)`:第 0 跳 `net.Dialer.DialContext`→`ssh.NewClientConn`;第 i 跳经 `client_{i-1}.Dial("tcp", hop.Addr)` 取底层 net.Conn 再握手;最后一跳转发连目标 addr。返回外层 client + 整链收尾闭包(sync.Once 幂等、逆序关全部中间 client,防中间跳泄漏)。
- 4 个方法(Run/RunWithStdin/RunStream/RunInteractive)改调 dialClient,删各自重复拨号段;`streamReadCloser`/`interactiveSession` 的 `client` 字段改为持有链收尾闭包。
- 错误定位:每跳失败包 `第N跳 user@host:port` 前缀再包 sentinel(`errors.Is` 链保持);`humanError` 透出跳数,但不透原始 OS 错误文本(维持"不泄敏感细节"纪律)。

## 3. 数据库迁移(双方言)

- 新增 `internal/store/migrations/sqlite/0065_server_jumps.sql`:`ALTER TABLE servers ADD COLUMN jumps TEXT NOT NULL DEFAULT '[]';`
- 新增 `mysql/0065_server_jumps.sql`:`ALTER TABLE servers ADD COLUMN jumps TEXT NULL;`(MySQL TEXT 不接受字面 DEFAULT,SELECT 已有 COALESCE 兜底)。

## 4. vault 删除占用检查 — `internal/vault/vault.go`

- `Delete` 的在用检查(现覆盖 sudo_credential_id):新增对 `servers.jumps` 的检查——取 jumps 非空行、Go 侧 JSON 解析后精确匹配 credentialID(免 LIKE 误报与 SQL 方言差异);命中返回 `ErrCredentialInUse`(HTTP 409)。

## 5. HTTP API — `internal/httpapi/servers.go`

- `serverDTO` 增加 `jumps []serverJumpDTO{host, port, user, credentialId}`(空→`[]`);create 请求体加 `jumps` 数组;update 加 `*[]`(nil=保留,非 nil=替换)。
- `writeServerError`:`ErrInvalidJump`→400 invalid_server(提示逐跳必填项与 ≤5 跳);`ErrCredentialTypeMismatch` 文案泛化为覆盖跳板场景。
- `POST /servers/{id}/test` 无需改动——Test→Exec 自动走全链,延迟含整链。

## 6. 前端

- `web/src/api/servers.ts`:新增 `ServerJump` 接口;`Server.jumps`、`CreateServerInput.jumps?`、`UpdateServerInput.jumps?`。
- `web/src/views/settings/SettingsServers.vue`:
  - 表单新增「跳板机(多跳)」动态行组(仿 ParametersPanel 的 addRow/removeRow):每行 主机/端口/用户/凭据下拉(与主凭据同过滤 ssh_key/ssh_password)+ 删除按钮,底部「添加跳板」;提示按连接顺序(第一跳最先连,目标经最后一跳到达)、最多 5 跳。
  - `validateForm` 增加逐跳校验;openAddModal/openEditModal 初始化与回填;提交时整体携带 jumps(替换语义)。
  - 列表行 user@host 旁显示「N 跳」徽标(jumps.length>0 时);跳板凭据名用现有 `credentialLabel` 解析(被删显示「已删除」)。
- i18n:`web/src/i18n/locales/<lang>/settingsServers.ts` 8 语言(zh-CN 为真源)新增 key:jumpTitle/jumpHint/jumpAdd/jumpRemove/errJump* 等;`keyParity.test.ts` 强制一致性。

## 7. 测试

- `internal/target` 单测:validateJumps(超限/缺字段/类型错配)、Create/Update/List 持久化 roundtrip、resolveSSHConfig 装配(fake vault + fake dialer 断言 cfg.Jumps 逐跳正确)。
- 真链路 e2e:沿用 `PIPEWRIGHT_E2E_SSH=1` 门控,新增多跳用例(localhost sshd 作跳板+目标,验证 Run 与 ExecInteractive 全链)。
- httpapi:DTO 含 jumps 的序列化与 update 部分语义(nil 不动 / [] 清空)。
- 前端:跑 keyParity/componentKeys/messageCompile 测试,补表单回填断言。

## 非目标

- git 仓库拉取(go-git transport)不接跳板链——其连接的是 git 服务而非目标服务器,技术栈独立。
- HostKey 校验策略维持现状(InsecureIgnoreHostKey,既有 DEFERRED 项)。
