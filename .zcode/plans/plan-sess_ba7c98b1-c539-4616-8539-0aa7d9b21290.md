# 为 webhook 接收端增加 Gogs/Gitea 头兼容

## 背景

当前 `internal/trigger/receiver.go` 只认 Gitee 协议（`X-Gitee-*` 头、Gitee 事件名、Gitee 验签算法），Gitea/Gogs 发来的 webhook 会被 401 拒绝。payload 结构（`ref`/`after`/`commits[]`/`pull_request.head.*`/`release.tag_name`）三方兼容，无需改动；卡点仅在头、事件名、验签三处。

Gitea/Gogs 协议要点：头为 `X-Gitea-Event/Signature/Delivery`（Gogs 同名 `X-Gogs-*`；Gitea 出于兼容同时发送两套头）；事件名为小写（`push`/`create`/`pull_request`/`release`）；签名为 `hex(HMAC-SHA256(key=secret, msg=原始请求体))`，放在 Signature 头里，无 timestamp。

## 改动

### 1. `internal/trigger/receiver.go`（核心）

- **头常量**（receiver.go:30-36 旁）：新增 `HeaderGiteaEvent = "X-Gitea-Event"`、`HeaderGiteaSignature = "X-Gitea-Signature"`、`HeaderGiteaDelivery = "X-Gitea-Delivery"` 及 `HeaderGogsEvent/Signature/Delivery` 三个对应常量，更新「冻结契约」注释。
- **事件名**：新增 `eventGiteaPush = "push"`、`eventGiteaCreate = "create"`、`eventGiteaPullRequest = "pull_request"`、`eventGiteaRelease = "release"`（Gogs 与 Gitea 取值一致）。`eventSubscribed`（receiver.go:385）增加四个 case：`push`→`ev.Push`、`create`→`ev.Tag`（Gitea 新建 tag/分支事件）、`pull_request`→`ev.PullRequest`、`release`→`ev.Release`。与 Gitee 的 `"Push Hook"` 等取值无碰撞，可安全共存。
- **Delivery 结构**（receiver.go:87-94）：新增两个字段：
  - `BodySignature string` — `X-Gitea-Signature`/`X-Gogs-Signature` 头（hex HMAC over RawBody）
  - `Actor string` — 提供商标签；空时回退 `"gitee"` 保持现有行为（receiver_test.go:98 断言不变）
- **verifySignature**（receiver.go:324）：重构为三条路径任一通过即可——现有密码模式、Gitee 签名模式不变；新增 `modeBody`：`BodySignature` 非空时计算 `hex(HMAC-SHA256(key=secret, msg=d.RawBody))` 恒定时间比较。注意去掉现有「TokenHdr 为空提前 return」对 body 签名路径的误伤。
- **timestampFresh**（receiver.go:352-356）：`modeBody` 与密码模式同待遇——timestamp 缺失放行（Gitea 协议不带 timestamp，无重放窗口可言）。
- **Handle**（receiver.go:180）：`Actor: "gitee"` 改为 `d.Actor` 回退 `"gitee"`。

### 2. `internal/httpapi/webhooks.go`（头解析）

`makeWebhookHandler`（webhooks.go:77-84）构查 Delivery 时按 fallback 链取头（Gitea 会同时发 X-Gitea-* 和 X-Gogs-*，故 Gitea 优先）：

- `Event` = `X-Gitee-Event` → `X-Gitea-Event` → `X-Gogs-Event`（第一个非空）
- `DeliveryID` = `X-Gitee-Delivery` → `X-Gitea-Delivery` → `X-Gogs-Delivery`
- `BodySignature` = `X-Gitea-Signature` → `X-Gogs-Signature`
- `Actor`：任一 `X-Gitea-*` 头存在 → `"gitea"`；否则任一 `X-Gogs-*` 存在 → `"gogs"`；否则 `"gitee"`

新增一个小 helper `firstHeaderValue(vals ...string) string`（trim 后取第一个非空）。

## 已知取舍（写进代码注释与提示文案）

- Gitea 推 tag 会同时发 `push`（ref=refs/tags/x）和 `create` 两个事件；若同时订阅 Push 和 Tag 可能产生两次运行，属 Gitea 事件模型使然，建议在 Gitea 端只勾选需要的事件（提示文案会带一句）。
- Gitea 端密钥留空 ⇒ 不发签名头 ⇒ 401 拒绝（安全正确行为），文案已提示必须填密钥。
