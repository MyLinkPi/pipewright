# 流水线克隆递归拉取子模块

## 背景

`internal/build/cloner.go` 用 go-git `PlainCloneContext` 克隆主仓库，无任何子模块处理——含 `.gitmodules` 的仓库克隆后子模块目录为空，Docker 构建上下文缺文件。生产接线中真正的克隆器是 `repocache.Cache`（`main.go:944` 注入，镜像命中走 `checkoutFromMirror` 本地出工作区，失败回退 `build.Cloner`），两条路径都必须支持子模块，否则启用镜像缓存后行为不一致。

go-git v5.19.1 自带的 `Submodules.UpdateContext` 不采用：其鉴权是单一 Auth 应用到所有子模块 URL（无法做 host 收口），相对子模块 URL 按父仓远端解析（在 repocache 下会错误地对本地镜像路径解析）。**只复用它的 `wt.Submodules()` 做解析**（`.gitmodules` 解析自带路径/名字加固，无文件时返回空表），拉取逻辑自研递归实现。

## 已确认策略

- **凭据同 host 才转发**（用户已选）：子模块解析出的 host 与父仓库一致才装配凭据（`gitauth.TransportAuth`，装配失败降级匿名）；跨 host 一律匿名拉取，匿名失败即克隆失败。
- 子模块拉取失败 → 构建失败（对齐原生 git `submodule update --init --recursive` 语义，不静默跳过留下空目录）。

## 改动

### 1. 新增 `internal/submodule/populate.go`（核心）

```go
// Populate 递归拉取 destDir 工作区 .gitmodules 声明的子模块到 pinned commit。
// allowInsecure 仅供测试放行 file:// 本地夹具，生产调用方传 false。
func Populate(ctx context.Context, destDir, parentURL string, cred vault.GitAuth, allowInsecure bool) error
```

内部 `populate(ctx, dir, parentURL, cred, insecure, depth)`（递归，depth 上限 16 防环）：

1. `gogit.PlainOpen(dir)` → `wt.Submodules()` 解析（无 `.gitmodules` → 空表直接返回）。
2. 每个子模块（`sub.Config()` 取 Name/Path/URL）：
   - **路径收口**：`filepath.Clean` 后拒绝绝对路径与 `..` 逃逸（防恶意 `.gitmodules` 穿越出工作区）。
   - **gitlink**：`sub.Status().Expected`（index 里的 pinned sha）；零值跳过（index 未注册，与 git 语义一致）。空 URL/Path → 报错。
   - **相对 URL 解析** `resolveSubmoduleURL(parentURL, subURL)`：绝对 URL（带 scheme 或 SCP `user@host:` 形态）原样；相对的按父 URL 形态拼接（http(s):// 用 `net/url`；SCP 手工拼前缀；本地路径 `path.Join`——仅测试路径会走到）。
   - **SSRF 收口**：`!allowInsecure && gitauth.ValidateRepoURL(resolved) != nil` → `ErrBlocked`（每个子模块 URL 都是仓库可控输入，与主仓同款校验）。
   - **鉴权** `submoduleAuth(resolved, parentURL, cred)`：`cred.Secret` 空 → 匿名；`gitauth.ParseRepoURL` 比对 host（EqualFold）相同才 `TransportAuth(resolved, cred)`，装配失败或跨 host → 匿名。
   - **拉取**：独立 `context.WithTimeout(ctx, 5*time.Minute)`（对齐 cloner 的 cloneTimeout）→ `PlainCloneContext(subDir, {URL: resolved, Auth, Tags: NoTags})` 全量克隆 → `wt.Checkout({Hash: pinned, Force: true})`；checkout 失败（孤儿 commit 不在任何分支尖）则 `FetchContext` 用 `+<sha>:<sha>` refspec 定向拉取后重试一次（go-git 自身同款回退）。
   - 递归 `populate(ctx, subDir, resolved, cred, insecure, depth+1)`。
3. 哨兵错误：`ErrBlocked`（SSRF/路径收口）；其余错误原样返回（由调用方映射，不带凭据明文）。

### 2. `internal/build/cloner.go`：Clone 末尾接线

checkout 完成、算出 `CommitShort` 后调 `submodule.Populate(ctx, destDir, repoURL, cred, c.allowInsecure)`；`ErrBlocked` → `ErrRepoBlocked`，其余失败 → `ErrCloneFailed`（沿用干净错误哨兵）。顺带修正 52-53 行陈旧注释（描述了不存在的"不限深度重试"）。

### 3. `internal/repocache/cache.go`：镜像检出后接线

`Clone` 中 `checkoutFromMirror` 成功后调 `submodule.Populate(ctx, destDir, repoURL, cred, c.allowInsecure)`（parentURL 用**真实远端 URL** 而非镜像路径，保证相对子模块 URL 解析正确；镜像只含超仓库对象，子模块必走网络）。失败**不**回退直连克隆（直连同网络同凭据，重试无益），直接返回错误。

### 4. 不改动（不产构建上下文）

`internal/ai/analyze.go`、`internal/ai/diff.go`、`internal/httpapi/source.go`（memfs 克隆，用于技术栈分析/diff/源码浏览）。

## 测试

- **`internal/submodule/populate_test.go`**：
  - `resolveSubmoduleURL` / `submoduleAuth` 表驱动：相对 `../lib.git` 对 https/SCP 父 URL 的解析；同 host 转发凭据、跨 host/空凭据/装配失败 → 匿名。
  - 集成（宿主无 git 则 skip，沿用 `internal/ai/analyze_test.go` 的 `makeBareRepo`/`localFileURL` fixture 模式）：构造 super 裸仓 + `.gitmodules` + `git update-index --add --cacheinfo 160000,<sha>,dep` 造 gitlink（不用 `git submodule add`，免 protocol.file 限制）→ 断言：子模块文件落盘且为 pinned sha 内容（子仓推进第二提交后仍检出旧版）；嵌套子模块递归拉齐；子模块 URL 指向 `169.254.169.254` → `ErrBlocked`；路径 `../evil` → 拒绝。
- **`internal/build`**：`&Cloner{allowInsecure: true}` 端到端 `Clone`（file:// fixture）断言子模块文件在工作区。
- **`internal/repocache`**：镜像命中路径下子模块同样拉齐，覆盖绝对与相对 `../sub.git` 两种 URL 形态。
