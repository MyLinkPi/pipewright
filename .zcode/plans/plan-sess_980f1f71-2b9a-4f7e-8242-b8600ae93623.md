# 安全隐患修复方案

修复上次审计发现的 6 项隐患。所有修复保持现有产品语义（单管理员 + 邀请制成员、cookie/CSRF 契约不变）。

## 修复 1（中）：登录锁定改为「按账户 + 按 IP」分桶，消除全局登录 DoS

现状：`LockoutManager` 是单一全局计数器，任何人用垃圾凭据失败 5 次即锁死全平台 15 分钟。

**`internal/auth/lockout.go`** — 重写为按 key 分桶：
- `entries map[string]*attemptRecord`（failCount / lockedUntil / lastFailAt），mutex 保护，沿用可注入 `Clock`（现有 `TestLockoutExpiry` 依赖 mockClock）
- key 规则：`"user:"+username`（阈值沿用 `LockoutThreshold=5`）、`"ip:"+clientIP`（新阈值 `ipLockoutThreshold=10`），锁定时长统一 `LockoutDuration=15min`
- `Guard(keys, authenticate)`：任一 key 处于锁定 → 拒绝；认证失败向所有 key 记失败；认证成功**只重置账户 key**（防止攻击者用已知账号穿插成功登录重置自己的 IP 计数）
- 惰性 GC：检查/记录时清理过期条目；map 超上限（10 万条）先清过期、仍超则整体重置（内存有界）
- 保持内存态不落库（重启清零为已知可接受残余，攻击者能重启进程则有更大攻击面）

**`internal/auth/service.go`**：
- `Authenticator.Login(username, password string)` → `Login(username, password, clientIP string)`（clientIP 为空则只按账户分桶，兼容服务层直测）
- `ChangePassword` 增加同款节流：当前口令验证失败按 `pwchange:` key 计数，达 5 次返回 `*ErrLockedOut`（15 分钟），修复「已持会话者可无限试当前口令」

**`internal/httpapi`**：
- `router.go:1203` 登录、`identity.go:106` 注册自动登录：传入 `clientIP(r)`（复用 `audit.go` 已有的防伪造提取逻辑）
- `account.go`：`errors.As(&auth.ErrLockedOut)` → 429

**测试**：更新 `internal/auth/identity_test.go`（14 处）、`bootstrap_test.go`（4 处）、`internal/identity/identity_test.go:224` 的 Login 调用签名；新增 lockout_test.go（账户 A 锁定不影响账户 B / 同 IP 轮换用户名 10 次锁 IP / 成功只重置账户计数 / 到期解除）；`httpapi/auth_test.go` 现有 TestLockout* 语义不变（同 IP 同账户场景）；account_test.go 加改密锁定 429 用例。

## 修复 2（中）：会话 token 落库改为 sha256 哈希

现状：`sessions.token` 存原始 token，拿到 DB 文件即可冒充任意活跃会话。

**`internal/auth/session.go`**：
- 新增 `hashToken(token) = hex(sha256(token))`；`Create` 落库哈希（返回给调用方的 `Session.Token` 仍是原始值）；`Get`/`Delete`/`DeleteOthers` 均先哈希再比对
- `List`：ID 即库内哈希前 16 位；`DeleteByIDPrefix` 改为 `DELETE ... WHERE token LIKE ?`，且先校验 id 为 `^[0-9a-f]{1,64}$`（防 `%` 之类通配符误删全部）
- **迁移**：新增 `internal/store/migrations/{sqlite,mysql}/0080_session_token_hash.sql`，内容 `DELETE FROM sessions;`——升级后所有既有会话一次性失效、全员重新登录（安全迁移的标准做法，两方言必须成对，`TestMigrationSetsMatch` 强制）

**测试**：新增会话哈希用例（落库值 ≠ 原始 token、Get/Delete/DeleteByIDPrefix 正常、非 hex id 拒绝）；现有 `TestSessionStoreIdentity` 等自动覆盖回归。

## 修复 3（中低）：反代部署下 Cookie 补 Secure 标志

现状：`setSessionCookies` 仅 `r.TLS != nil` 时设 Secure；本项目自己的 platformHTTPS（本机 nginx 终止 TLS）形态下永远不设。

**`internal/httpapi/router.go` `setSessionCookies`**：`secure := r.TLS != nil || (trustedProxyRequest(r) && X-Forwarded-Proto == "https")`。`trustedProxyRequest` 复用 `audit.go` 的 `trustForwardedHeader() || isLoopbackHost(remoteAddr)` 判定（与 clientIP 同一信任模型；已确认 platformhttps 生成的 nginx 会下发 `X-Forwarded-Proto`，无需改模板）。

**测试**：httptest 客户端 RemoteAddr 本就是 127.0.0.1，直接发 `X-Forwarded-Proto: https` 断言两个 cookie 带 Secure；不带头则无 Secure。

## 修复 4（低）：/version 移入认证组

已确认前端仅在登录后的设置页调用（`SettingsSystem.vue`），登录页不依赖；移到受保护组内还能顺带修好 dev 模式下 Vite 代理不覆盖 `/version` 的问题。

- `router.go`：删除公开 `r.Get("/version")`，在 `/api` 组内加 `ar.Get("/version", handleVersion)`（GET 免 CSRF，带会话 cookie 即可）；`/healthz` 保持公开供探针
- `web/src/api/version.ts`：`http.get('/version')` → `'/api/version'`
- 测试：未登录 401 / 登录后 200

## 修复 5（低）：全局安全响应头（CSP / 防点击劫持）

已确认前端构建产物无内联脚本/样式、无外部源、字体自托管、WS/SSE 同源、Monaco worker 同源——严格 CSP 可行。

**`internal/httpapi/router.go`**：新增中间件 `r.Use(securityHeaders)`，对全部响应设置：
- `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self' data:; connect-src 'self'; worker-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'`
- `X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`、`X-Content-Type-Options: nosniff`

approvals 页 handler 用 `Set` 覆盖同值头，无冲突。测试：抽样断言响应头。

## 修复 6（低）：docker-compose MySQL 默认弱口令

`docker-compose.yml`：`MYSQL_PASSWORD`/`MYSQL_ROOT_PASSWORD` 去掉 `pipewright`/`rootpw` 默认值（改为 `:-` 空默认；不用 `:?` 必填语法——Compose 解析期插值会让未启用 mysql profile 的用户也报错）。`.env.example`：MySQL 段改为注释占位 + 必须设置强口令的说明。

## 验证

1. `go build ./...`、`go vet ./...`
2. `go test ./internal/auth/... ./internal/httpapi/... ./internal/store/... ./internal/identity/...`，然后全量 `go test ./...`
3. 前端仅 version.ts 一行改动，跑 `npm run type-check`（如无此脚本则 build 校验）

## 明确不做（并在总结中说明）

- 锁定状态持久化到 DB（重启清零）：残余风险低，保持内存态
- 全站通用 IP 限流中间件：登录路径已由按 IP 锁定覆盖，其余公开入口均有高熵令牌/签名兜底，通用限流建议留在网关层
- 一次性全员会话失效（迁移删 sessions）造成的重新登录是预期行为，会在交付说明中标注
